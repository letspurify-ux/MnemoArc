# 백엔드 리뷰 및 수정 — 2026-09-27

백엔드에서 8건의 오류를 재현하고 수정했다. 각 오류는 수정 전 실패하는 회귀 테스트를 추가해 확인했으며, 수정 후 전체 Rust 테스트와 정적 검사를 통과했다.

## 검토 범위

- 로컬 Web API의 세션 소유권, 실행 중 설정 병합, 인증 정보 보존
- 에이전트의 취소·제한 시간·도구 실행 결과 처리, 작업 재개와 체크포인트 이후 요청 보존
- 모델 HTTP 응답, SSE 스트림 조립, 연결 확인
- 파일 경로 제한, 검색 범위, 편집·롤백과 DB 쓰기의 실행 경계
- 기존 기억·문서 검토·출처·실행 기록 테스트의 회귀 여부

## 발견한 오류와 수정

| 우선순위 | 재현 조건과 영향 | 수정 |
|---|---|---|
| P1 | DB 커밋 결과 불명, 파일 롤백 실패, 외부 쓰기 중 잡힌 패닉이 도구 오류로 반환되어도 쓰기 차단 상태가 설정되지 않았다. 같은 응답의 후속 호출이나 다음 실행이 추가 변경을 수행할 수 있었다. | 워커가 정상 반환한 경우에도 오류의 의미를 검사한다. 결과가 불확실한 외부 쓰기는 공유 차단 상태에 기록하고, 후속 호출과 새 실행을 막으며 최초 오류를 보존한다. |
| P2 | 실행 중 API 키를 변경하거나 삭제한 뒤 다른 설정을 `credential_mode=keep`으로 저장하면, 아직 적용되지 않은 키 선택 대신 이전 실행의 키를 복원했다. | 키 유지의 기준을 최신 `pending_config`로 변경했다. 대기 설정이 없을 때 현재 설정을 사용한다. |
| P2 | `Session::add_user("계속 진행")`이 `latest_request`를 덮어썼다. 원문이 체크포인트로 활성 문맥에서 제외된 후에는 요구사항·관련 기억 검색·후속 질문에 재개 문구가 원래 요청처럼 전달되었다. | 재개 문구는 대화 기록에 추가하고 원래 요청은 유지한다. 명시적인 새 작업은 계속 새 요청으로 전환한다. |
| P2 | SSE의 CR 단독 줄바꿈, 혼합 줄바꿈, UTF-8 BOM을 처리하지 못해 이벤트를 놓쳤다. `trim_start`는 데이터의 의미 있는 선행 공백도 제거했다. | 바이트를 순서대로 처리하는 파서로 변경했다. 청크에 걸친 CRLF·BOM을 처리하고 `data:` 뒤의 선택적 ASCII 공백 한 개만 제거한다. 이벤트 크기 제한을 유지한다. |
| P2 | `[DONE]` 뒤에 같은 HTTP 청크로 들어온 이벤트도 처리했다. 이미 완료된 응답이 뒤따르는 오류 이벤트 때문에 실패하여 청크 분할에 따라 결과가 달라졌다. | 완료 마커를 받으면 해당 이벤트 처리 루프를 즉시 끝낸다. |
| P2 | 연결 확인이 일반 응답의 HTTP 상태만 확인했다. 200 HTML·오류 JSON을 받은 경우나 도구 결과 뒤에 최종 텍스트가 없는 경우에도 성공을 표시했다. | 일반 응답 본문을 시간·크기 제한 안에서 읽고 JSON과 텍스트 완료 여부를 검사한다. 도구 왕복 후에도 완전한 최종 텍스트 응답이 있어야 성공한다. |
| P2 | 검색의 실제 디렉터리 `path`를 glob으로 변환했다. `[route]`는 다른 한 글자 디렉터리를 검색하고, `{routes,handlers}`나 닫히지 않은 `[`가 있는 이름도 잘못 해석했다. | 디렉터리 범위를 실제 경로의 구성 요소로 비교한다. 검색 커서에도 디렉터리 범위를 포함한다. |
| P2 | `include=["**/*.rs"]`를 디렉터리 자체에 적용해 `path="src"` 또는 `path="."` 검색을 거부했다. | 디렉터리 접근에는 제외 규칙을 적용하고, 포함 규칙은 열거한 파일에 적용한다. 직접 파일 검색과 자식 파일의 제외 규칙도 검증했다. |

## 설계와 회귀 검증

- 불확실한 쓰기에는 기존 공유 차단 상태를 사용한다. 확인된 롤백과 읽기 실패는 이 상태를 설정하지 않는다. 실제 변경 내용을 확인하고 앱을 재시작한 뒤 작업을 진행할 수 있다.
- 설정 변경은 다음 요청 경계에 적용하는 기존 방식을 유지한다. 키 변경·삭제 후 연속 저장이 최신 인증 선택을 보존하는지 확인했다.
- SSE 테스트는 한글·이모지·BOM·줄바꿈을 모든 두 청크 분할 위치와 한 바이트씩 전달하는 방식으로 검사한다.
- 검색 테스트는 특수 문자가 있는 실제 폴더, 하위 폴더, 다음 페이지, 다른 범위의 커서 거부, 포함·제외 규칙을 검사한다.
- 외부 서비스 오류는 로컬 HTTP 서버와 도구 워커 반환값 주입으로 재현했다. 실제 DB 커밋 중 네트워크를 끊는 테스트는 수행하지 않았다.

새 회귀 테스트 8개는 [에이전트 단위 테스트](../src/agent.rs), [Web 단위 테스트](../src/web.rs), [작업 상태 테스트](../tests/core.rs), [스트리밍 테스트](../tests/streaming.rs), [검색 테스트](../tests/search.rs)에 있다. 기존 Clippy 경고 두 곳도 동작 변경 없이 정리했다.
