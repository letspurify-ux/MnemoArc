# 체크포인트 실패 및 유사 복구 경로 점검

2026-09-20. 실패 세션의 읽기 전용 API 기록과 backend 제어 흐름을 대조했다. 실제 공급자 호출이나 사용자 세션 재실행 없이, 결정적인 모의 LLM 회귀 테스트로 복구 동작을 검증한다.

## 원래 실패

체크포인트 유지보수 묶음 19·20은 각각 기억 저장에 성공했지만 완료 호출을 하지 않았다. 묶음 21은 compact outline만 본 context.rs에 존재하지 않는 출처 S93을 붙여 저장하다 실패했다. 기존 구현은 정상 저장을 포함한 모델 요청 세 번을 모두 재시도로 취급해, 오류를 고칠 다음 요청 전에 중단했다. 두 기억과 원문은 보존돼 있었다.

## 점검 범위와 조치

| 경로 | 확인 및 조치 |
| --- | --- |
| checkpoint 준비·전송·완료·재개 | 실패 요청과 전체 요청을 분리했다. 실패 3회 또는 전체 6회로 제한하고 최초 배치 오류를 보존한다. 한 배치에서 저장과 완료가 모두 실패해도 실패 요청은 한 번만 센다. 전송 전 예산·이벤트 전달 시간 검사를 통과해야 횟수를 쓴다. 재개는 실패·승인 상태까지 초기화한다. |
| 출처 검증·기억 저장·조사 항목 검증 | 공통 source_refs의 오류 안내가 checkpoint에서도 가능한 source_lookup/history로 연결된다. source_lookup은 세션과 기억에 보존된 근거만 경로/ID로 조회하며, 없는 근거는 반환하지 않는다. compact outline 위치나 symbol_id를 관측 출처 ID로 취급하지 않는다. 근거 없는 사실 저장을 허용하는 우회는 추가하지 않았다. |
| 도구 배치·원문 아카이브·오류 축약 | 긴 오류가 아카이브로 넘어가도 오류 코드와 앞부분을 보존한다. 상세 원인은 history로 확인할 수 있다. 실패한 배치가 승인되지 않고 원문을 유지하는 기존 보호 조건도 검증한다. |
| 출력 길이 초과·이어 생성 | 연속 길이 초과 3회 제한은 유지하고, 완전한 응답을 받으면 해당 복구 카운터를 초기화한다. 서로 다른 작업 단계의 잘림이 누적돼 중단되는 결함을 수정했다. |
| 문서 검토 후 수정 예산 | 전체 task_rounds 차이 대신 실제 수정 요청 수를 센다. 체크포인트 유지보수는 8회 수정 예산을 소모하지 않는다. |
| 문서·답변 검토 응답 | 빈 응답·잘린 응답·금지된 도구 호출, 문서 검토의 잘못된 JSON은 최대 3번 안에서 재요청한다. 직전 오류를 검토 입력에 전달한다. 유효한 내용 검토 횟수와 형식 실패를 분리한다. 금지된 도구는 실행하지 않으며, 반복 실패하면 원본 문서·초안을 보존한다. |
| HTTP/SSE 공급자 재시도 | 기존 공급자 오류별 재시도, 취소, 요청 타임아웃 경계를 확인했다. 429/5xx와 형식 오류의 제한적 재시도 정책은 유지한다. |
| 파일·심볼·페이지 커서 및 문서 수정 충돌 | 버전/해시 불일치 시 재조회하도록 하는 기존 동작을 유지한다. 오래된 근거·커서나 충돌한 쓰기를 성공으로 취급하지 않는다. |
| 메모리 용량·history prune·설정 축소 | 데이터 보존 및 원자적 거부 정책을 유지한다. 복구 횟수를 늘려 실제 컨텍스트·실행 예산 검사를 우회하지 않는다. |
| 최종 검증·반복 작업·취소·패닉 | 불완전 조사 preflight는 검토 예산을 소모하지 않는 기존 처리를 확인했다. 제한된 최종 재검토, 반복 탐색 정지, 완료 쓰기 보존, 취소 및 패닉 경로는 기존 테스트를 포함해 검증한다. |

## 회귀 시나리오

- 정상 저장 2회 → 미등록 출처 실패 → 기존 출처 조회 → 수정 저장 및 완료.
- 같은 배치의 저장 오류와 후속 완료 오류는 실패 요청 1회로 계산하고 최초 원인 유지.
- 성공한 조회만 반복하고 승인하지 않는 모델은 총 6회에서 정지.
- 기억에만 남은 근거 조회, 없는 경로 조회, 이전 Checkpoint JSON 역직렬화.
- 긴 오류의 원인 코드 및 원문 아카이브 유지.
- 별개 단계에서 발생한 세 차례 출력 잘림은 각각 복구 가능; 연속 잘림은 기존 한도 유지.
- 체크포인트 유지보수 이후 문서 수정 예산 유지; 실제 수정 8회 제한 유지.
- 잘못된 검토 JSON·빈 답변 검토의 회복과 반복 실패 상한.

## 적용 범위와 한계

정리 공간은 기본 세 요청분을 예약하며, 추가 복구는 실제 전송 전 컨텍스트·실행 예산이 허용할 때만 진행한다. 모델의 임의 출처 생성 자체를 막는 보장은 없지만, 잘못된 근거를 승인하지 않고 복구할 도구와 기회를 제공한다.

실행 중인 서버는 메모리에 사용자 세션을 보관하므로 재시작하지 않는다. 코드 변경은 다음 빌드/서버 시작에 적용된다. 실제 공급자에서의 전체 문서 생성 성공은 이번 모의 테스트와 별개의 검증 항목이다.

## 검증 결과

- `npm test`: Rust 163개, 실행 스크립트 3개, 프런트엔드 4개 통과. 실제 공급자/실행 환경 의존 테스트 5개는 기존 ignore 정책에 따라 제외.
- `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, `git diff --check` 통과.
- 실제 API 사용량을 발생시키는 라이브 LLM 테스트 및 브라우저 E2E는 이번 검증에 포함하지 않았다.
