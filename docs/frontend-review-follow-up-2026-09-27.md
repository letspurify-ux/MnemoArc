# 프론트엔드 후속 리뷰 — 2026-09-27

## 범위

[첫 리뷰](frontend-review-2026-09-27.md)의 수정 사항을 유지하면서 설정·프로젝트 초안과 서버 갱신, 조회 취소, 이전 대화 병합, 폴더 선택창의 키보드 동작을 다시 점검했다. 변경한 UI가 내장된 Rust 실행 파일로 검증했다.

수정 전에 추가한 브라우저 사례 5개와 이력 병합 단위 사례 2개가 실패하는 것을 확인했다. 수정에 따른 적용 범위 전환, 연결 확인, 타임아웃 복구, 전송 잠금도 회귀 검사에 포함했다.

## 발견한 문제와 수정

| 우선순위 | 재현 조건과 영향 | 수정 |
| --- | --- | --- |
| 높음 | 설정 화면을 열어 둔 채 다른 창에서 설정을 변경하면, 화면의 초안은 처음 값에 머물렀다. 모델 이름만 바꾸어 저장해도 최신 DB 설정이나 프로젝트 목록을 이전 값으로 덮어쓸 수 있었다. | 마지막 서버 값·현재 초안·새 서버 값을 비교한다. 사용자가 편집한 항목은 유지하고, 편집하지 않은 항목은 최신 값으로 갱신한다. 중첩된 DB 설정에도 같은 규칙을 적용한다. |
| 보통 | 프로젝트 관리에서 편집하지 않은 목록도 외부 변경을 반영하지 않았다. 선택한 프로젝트가 삭제되면 이전 프로젝트를 계속 편집했다. 세션 프로젝트도 이름을 편집하는 동안 받은 최신 작업 목적을 저장 시 덮어썼다. | 세 편집기에 같은 초안 관리 훅을 사용한다. 프로젝트 목록이 줄어들면 유효한 항목을 선택하고, 세션 프로젝트의 편집하지 않은 필드를 갱신한다. |
| 보통 | 이전 세션 상세 조회가 멈추면 새 세션을 선택해도 그 요청이 끝날 때까지 화면을 열지 못했다. 늦은 이전 요청의 오류도 새 화면에 표시할 수 있었다. | 세션 전환 시 기존 조회를 취소하고 즉시 새로 조회한다. 요청 소유자와 선택 순서를 확인해 응답·오류·잠금 해제를 적용한다. 상태 조회에는 15초 제한을 두고 이후 갱신으로 복구한다. |
| 보통 | 전송 성공 응답 직후 화면은 이전 상태인데 전송 잠금이 풀릴 수 있었다. 저장 후 갱신도 기존 조회가 진행 중이면 실제 갱신을 기다리지 않았다. | 작업과 저장 후에는 기존 조회를 교체하고 새 상태 조회가 끝날 때까지 기다린다. 이후 입력한 초안은 기존 편집 버전 검사로 보존한다. |
| 보통 | 대화 3–4를 보며 이전 페이지 1–2를 요청한 뒤 최신 페이지가 7–8로 바뀌면, 늦은 페이지가 1–2와 7–8을 합치고 `previous`를 없앴다. 중간 대화를 다시 조회할 수 없는 상태가 됐다. 정리된 과거 페이지가 비어 있는 경우에도 같은 문제가 있었다. | 현재 이력과 연결되지 않거나 모두 정리된 이전 페이지는 현재 커서를 바꾸지 않는다. 정리 경계는 계속 반영하고, 연결되는 페이지를 받은 뒤 과거 방향으로 확장한다. |
| 보통 | 폴더 선택창에 초기 포커스와 키보드 이동 제한, Escape 닫기가 없었다. 키보드로 뒤의 프로젝트를 바꾼 뒤 다른 프로젝트에 경로를 적용할 수 있었다. | 네이티브 `dialog`를 모달로 열어 배경 조작을 막는다. Tab·Shift+Tab을 내부에서 순환시키고, Escape 또는 닫기 후 원래 버튼에 포커스를 돌린다. 외부 갱신으로 소스 폴더가 바뀌면 선택창도 새 경로를 조회한다. |

## 설계와 적용 범위

- **초안 병합:** 객체는 필드별로 비교한다. 프로젝트·쿼리 배열은 고정 ID가 없어 하나의 값으로 취급한다. 편집 중인 배열을 서버 배열의 같은 위치와 임의로 합치지 않는다.
- **저장 이후:** 성공한 제출 값을 비교 기준으로 바꾼다. 이후 서버가 정규화한 값은 받아들이고, 저장 요청 중에 추가로 편집한 값은 유지한다. 전역·세션 적용 범위를 바꾸면 해당 서버 값으로 초안을 초기화한다.
- **연결 확인:** 검사 중 사용자가 편집한 경우뿐 아니라, 서버 갱신으로 현재 초안이 달라진 경우에도 다시 확인하도록 안내한다.
- **조회 취소:** 취소 대상은 작업 공간의 상태 조회다. 서버에서 수행 중인 모델 작업은 세션 전환으로 중단하지 않는다. 취소된 요청의 종료 처리가 새 요청의 잠금이나 타이머를 해제하지 못하게 한다.
- **저장 충돌의 경계:** 이 수정은 이미 관측한 서버 변경을 오래된 초안으로 덮어쓰는 문제를 다룬다. 같은 필드를 양쪽에서 편집하면 로컬 초안을 우선한다. HTTP 저장 직전에 다른 클라이언트가 동시에 쓰는 상황에 대한 서버 측 버전 충돌 검사는 현재 API에 없다.

## 검증 결과

| 명령·검사 | 결과 |
| --- | --- |
| `npm test -w frontend` | 18개 통과. 이번 리뷰에서 초안 병합 4개와 이력 경합 2개 추가 |
| `npm run build -w frontend` | 성공 |
| `cargo build` | 최신 UI를 내장한 실행 파일 빌드 성공 |
| `npm run test:ui -w frontend` | 46개 통과. 이전 35개와 추가 11개 |
| `git diff --check` | 통과 |
| 데스크톱 1440×980, 모바일 390×680 | 폴더 선택창 캡처 확인, 경계·포커스·Escape 검증 |

브라우저 검사는 macOS Chrome과 임시 설정의 Rust 서버·로컬 LLM fixture를 사용했다. 기존 설정 저장·키 보존·스트리밍 Markdown·수식·Mermaid·세션 취소·완료 검증·문서 다운로드도 다시 통과했다. 추가 회귀 검사는 처리되지 않은 JavaScript 오류가 없는지도 확인한다. 외부 모델 공급자와 실제 Oracle 연결은 이 검사에 포함하지 않았다. Vite의 기존 500kB 초과 청크 경고는 남아 있다.

새 세션 생성에 대한 기존 지연 응답 테스트는 취소된 요청에서 브라우저 응답 이벤트가 발생하지 않는 점을 반영했다. 지연 fixture가 처리를 마친 뒤 세션 목록과 선택 URL을 검사한다.
