# 의미·검색 복구·Java 탐색 회귀 평가

2026-09-20에 등록된 `llm_agent` 프로젝트와 설정된 `z-ai/glm-5.3-flash`를 사용해 실제 모델을 검증했다. 구현과 평가 코드는 Rust이며, `tests/navigation_eval.rs`에 재실행 가능한 테스트를 추가했다. 기존 결과 문서와 대상 소스는 보존했다.

## 평가 대상

1. **의미 정확성**: 실제 `server.js`, `agent.js`, `abort.js`에서 기존 Error 객체 재전파, 새 AbortError 생성의 조건, 정상 연결 종료, 원래 promise의 취소 여부, 신호 전달과 응답 쓰기의 순서를 검사한다. 다섯 개의 정답 필드를 비교하고 실제 전달된 코드 및 인용 범위를 확인한다.
2. **검색 복구**: `close|req.on|res.on`을 문자 검색해 실제 빈 결과를 만든 뒤 그 도구 응답을 모델에 전달한다. 모델이 범위를 유지한 더 짧은 검색이나 명시적인 정규식으로 복구하고 실제 구현을 읽는지 검사한다. 기록된 호출 수는 주입한 최초 실패 1회를 제외한 추가 호출이다.
3. **Java 탐색**: 실사용 Java 저장소가 로컬에 없어 Rust 테스트가 임시 Java 프로젝트를 만든다. 두 파일에서 오버로드, 중첩 클래스의 동명 메서드, 파일 간 위임, 정수 0·음수, null 처리를 조사한다. 실제 모델이 Tree-sitter 도구와 본문 읽기를 사용한다. Java 프로그램을 실행하는 테스트나 대규모 Java 저장소 벤치마크는 아니다.

정답과 줄 범위만 맞는 추측을 통과시키지 않도록, 핵심 구현 줄이 최종 도구 응답의 출처에 포함됐는지도 검사한다. 명시적인 동작 설명 주석은 인용으로 허용하지만 해당 구현까지 읽어야 한다. 간결 구조 목록만 조회한 결과는 본문 근거로 인정하지 않는다. 이 검사는 준비된 사례의 핵심 사실을 평가하며 모든 자연어 문장의 의미를 자동 검증하지는 않는다.

## 관측 결과

판정기를 보정한 뒤 각 항목을 새 세션에서 3회씩 실행했다.

| 항목 | 관측 결과 | 도구 호출 수 |
|---|---|---|
| 의미 | 핵심 정답은 3/3. 한 답변이 실행 순서를 설명하면서 응답 쓰기 위치의 인용을 빠뜨림 | 5, 5, 7 |
| 검색 복구 | 검색 복구 3/3. 한 답변이 `receiver`에 설명을 붙이고 메서드를 `res.once`로 적어 엄격한 필드 형식 검사에 실패함 | 3, 2, 3 |
| Java | 정답·인용·읽기 근거 3/3. 한 실행에서 `Service.Inner`를 두 번 조회해 낭비가 발생함 | 4, 6, 12 |

평가 준비 과정에서는 JSON 코드 블록 뒤의 설명을 내용 오류로 오인하는 판정기 문제를 발견해 수정했다. 정답은 JSON 객체에서 판정하고 뒤의 설명문 전체가 검증됐다고 간주하지 않는다. 정답 누락, 잘못된 값, 유효하지 않은 인용, 읽지 않은 구현은 계속 실패 처리한다. 형식 문제로 원문을 보존하지 못한 초기 실행은 위 비교 수치에서 제외했다.

## 반영한 수정

- `source_search`에 단일 파일용 `path`를 추가했다. 실제 모델이 `file_read`와 같은 인자를 사용해 거부되던 사례를 해결한다. glob과의 혼용, 프로젝트 밖 경로, 제외 파일은 거부하고 파일 변경·범위 변경 시 커서 검사를 유지한다.
- 구조 결과에 `qualified_name`을 추가했다. 자식 조회 시 부모의 이 값을 `container`로 복사한다. 잘못된 소속 필터로 비면 가능한 소속 경로와 재조회 안내를 반환한다. Java의 점 표기를 자동 변환하거나 존재하지 않는 심볼을 대신 선택하지 않는다.
- 실행 순서를 설명할 때 양쪽 연산을 인용하고, 오류 동작은 오류를 선택하는 분기를 인용하도록 안내했다.
- 자동 평가에 정답·출처·실제 읽기 근거 검사와 판정기 자체의 회귀 테스트를 추가했다. 설정된 출력 문서 대신 임시 출력 경로를 사용하며 예상치 못한 문서 쓰기를 실패 처리한다.

최종 수정 후 세 항목을 각각 한 번 더 실행했다. 세 실행 모두 정답·근거·도구 호출 검사를 통과했고 도구 오류는 없었다.

| 항목 | 호출 수 | 공급자 입력 토큰 | 출력 토큰 |
|---|---:|---:|---:|
| 의미 | 6 | 47,811 | 813 |
| 검색 복구 | 2 | 25,811 | 282 |
| Java | 6 | 22,366 | 683 |

최종 실행에서는 단일 파일 검색의 `path`가 실제로 사용됐다. 검색 복구는 같은 파일에서 `close`를 다시 검색한 뒤 관련 줄만 읽었다. Java는 두 번의 간결 구조 조회와 네 번의 심볼 읽기로 끝났으며, 잘못된 중첩 경로를 반복 조회하지 않았다. 소규모·단일 모델의 결과이며 반복 실행마다 최소 호출 수나 정확도를 보장하지 않는다.

## 재실행

일반 테스트는 유료 API를 호출하지 않는다.

```sh
cargo test --test navigation_eval
```

명시적으로 유료 모델 평가를 실행하려면 저장된 설정과 인증 정보를 사용한다. 모델 응답 전문이나 세션 대화 전체 대신 최종 답변·도구 호출·판정 결과를 선택한 보고서 경로에 저장한다. 인증 정보는 보고서에 포함하지 않는다.

```sh
MNEMOARC_LIVE_TEST=1 \
MNEMOARC_NAV_REPETITIONS=3 \
MNEMOARC_NAV_REPORT=/tmp/mnemoarc-navigation-report.json \
cargo test --test navigation_eval live_navigation_regressions -- --ignored --nocapture
```

`MNEMOARC_LIVE_CONFIG`로 설정 파일을 바꿀 수 있다. `MNEMOARC_NAV_CASES=semantics,recovery,java,branches`에서 원하는 항목을 고를 수 있으며 반복 수는 1~5다. 실제 프로젝트 소스가 바뀌면 기대 사실과 근거 위치를 다시 검토해야 한다. Java fixture는 Rust 테스트 코드에 포함되어 동일하게 재생성된다.

최종 일반 테스트 131개, Clippy, 포맷 검사, 릴리스 빌드가 통과했다. 일반 실행에서 제외되는 유료 테스트는 3개이며 위 실제 모델 평가는 별도로 실행했다.

## 후속 효율 개선

새 세션 기본 탐색 도구, 구문 트리 캐시, 호출·토큰 상한 검사와 추가 실측은 [소스 탐색 효율 개선](navigation-efficiency-improvement.md)에 기록했다. 후속 실측에는 의미·인용·비용 기준 실패가 남아 있으므로 위 과거 통과 결과를 현재 실행의 안정성 보장으로 해석하지 않는다.

소스 답변 1회 검토와 문자 OR 검색의 설계·후속 평가 조건은 [소스 답변 검토](source-answer-review.md)를 참고한다. `MNEMOARC_NAV_REVIEW=off`는 검토만 끄는 비교 옵션이다.
