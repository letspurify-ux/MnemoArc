# 백엔드 추가 정밀 리뷰 — 2026-09-27

기존 [백엔드 리뷰](backend-review-2026-09-27.md) 이후의 코드에서 추가 버그 6건을 재현하고 수정했다. 각각 수정 전 실패하는 테스트로 확인했으며, 실제 Oracle 접속 없이 검사할 수 있는 입력 경계와 로컬 HTTP 서버를 사용했다.

## 검토 범위

- Web API의 세션 소유권, 실행 중 설정 병합, 인증 저장과 취소·종료 흐름
- 에이전트의 병렬 읽기 결과 병합, 호출 결과 재사용, 작업 재개, 체크포인트와 후속 질문
- 기억의 개정·참조 보호와 컨텍스트 예산
- 파일 경로 제한, 문서 및 일반 파일 편집, 저장 후 검증과 읽기 범위 기록
- 모델 응답의 SSE 처리와 오류·재시도 경계
- Oracle 조회·변경 호출의 인자 검증과 값 변환

## 재현한 문제와 수정

| 우선순위 | 문제와 영향 | 수정 |
|---|---|---|
| P1 | `type=number`의 문자열 값을 `serde_json::Number`로 파싱하면서 정밀도를 잃었다. 예를 들어 `12345678901234567890.123456789012345678`이 `1.2345678901234567e+19`로 바뀌어 DB 호출에 다른 값이 전달될 수 있었다. | 십진수 문법과 길이를 검사하고 원래 문자열을 숫자 바인드에 전달한다. 소수·큰 정수·지수 표기를 부동소수점으로 변환하지 않는다. |
| P2 | 프로시저·함수 인자의 `direction` 또는 `type`에 `null`, 숫자, 불리언 등을 넣어도 각각 `in`, `string`으로 조용히 대체했다. 잘못된 요청이 다른 인자 형식으로 실행될 수 있었다. | 필드를 생략한 경우에만 기본값을 사용한다. 명시한 값의 형식이 잘못되면 DB 접속 전에 거부한다. |
| P2 | SQL의 `params`가 `item_id`와 `ITEM_ID`를 함께 허용했다. Oracle에서는 같은 바인드 이름이므로 서로 다른 값이 같은 자리를 대상으로 지정되었다. | 바인드 이름을 대소문자 구분 없이 중복 검사한다. |
| P2 | 서로 다른 상위 절 아래에 같은 제목이 있으면, 전체 `section_path`로 읽기에 성공해도 전달 범위 기록은 짧은 제목으로 절을 다시 찾다가 실패했다. 읽은 절이 계속 미열람으로 표시되었다. | 실제 읽기에 사용한 전체 절 경로로 범위를 기록한다. 결과 크기 제한에 따른 페이지 이어 읽기에서도 이 경로를 유지한다. |
| P2 | 기존 문서를 임시 파일로 교체할 때 파일 권한이 임시 파일의 기본값으로 바뀌었다. Unix에서 `0640` 문서를 수정하면 `0600`이 되어 그룹 읽기 권한이 사라졌다. | 기존 파일의 권한을 임시 파일에 적용한 뒤 동기화하고 교체한다. 단일 편집과 배치 편집이 같은 저장 함수를 사용한다. |
| P2 | `[DONE]` 뒤에 같은 HTTP 청크로 잘못된 UTF-8 데이터가 오면, 청크 전체를 먼저 해석하던 SSE 파서가 이미 완료된 응답까지 실패시켰다. | 이벤트를 순서대로 전달하고 완료 표식을 받는 즉시 처리를 끝낸다. 뒤따르는 바이트를 먼저 해석하지 않는다. |

## 설계와 검증

- 숫자 문자열은 기존에 받던 JSON 십진수 문법을 유지하며, `NaN`, 잘못된 소수, SQL 구문 등이 숫자로 전달되지 않도록 검사한다. 이미 JSON 숫자로 파싱된 값의 정밀도를 복원하는 변경은 아니다. 정밀도가 중요한 프로시저·함수 숫자 인자는 `type=number`와 십진수 문자열 `value`를 사용한다.
- DB 인자 오류는 공통 `invalid_database_execution_arguments` 오류로 반환한다. 실제 도구 진입점에서도 연결 전에 거부되는지 확인했다.
- 문서 읽기 테스트는 반복 제목의 다른 절에 읽기 기록이 잘못 붙지 않는지 검사한다. 별도 입력 문서, 결과 문서, LF·CRLF, 여러 결과 페이지를 포함한다.
- 문서 저장은 기존 내용 해시 검사·취소 확인·원자적 교체를 유지한다. 파일 권한 회귀 테스트는 Unix에서 실행한다.
- SSE의 기존 바이트 분할·혼합 줄바꿈·BOM·크기 제한·도구 호출·재시도 테스트도 함께 검사한다.

## 검증 범위의 한계

실제 Oracle 연결 테스트는 접속 환경변수가 없어 조기 반환되었다. 테스트 실행기의 passed 집계에는 포함되지만 실DB 검증을 의미하지 않는다. 숫자 값은 Oracle 드라이버에 넘기기 전까지의 보존을 테스트했고, 설치된 드라이버가 NUMBER 문자열을 부동소수점으로 변환하지 않는 경로도 확인했다. 유료 모델 테스트 5개는 실행하지 않았다. 나머지 ignored 1개는 부모 테스트가 별도 프로세스로 실행하는 프록시 보조 테스트다.
