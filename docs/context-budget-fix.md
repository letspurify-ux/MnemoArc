# 컨텍스트 한도 오류 수정 및 검증

## 확인한 원인

실행 중이던 `llm_agent` 세션을 읽기 전용 API로 조사했다. 오류는 공급자 응답이 아니라 MnemoArc의 요청 전 검사에서 발생했다. 기억 저장은 0건, 완료된 체크포인트도 0회였다.

- 미지원 모델 이름을 UTF-8 바이트 수로 계산하면서 기억 메타데이터에도 160이라는 고정 제한을 적용했다. ID와 JSON 구조만 121바이트였으며, 실제 저장 시도는 458/474, 재시도도 298/331로 계산되어 모두 실패했다.
- 실패한 기억 저장의 긴 인자가 대화에 남았다. 활성 메시지가 48,081바이트로 커졌으며, 프롬프트·도구·현재 상태를 합치면 요청 입력 허용량 55,488을 초과했다.
- 도구와 실행부가 각각 JSON 문자열을 `preview`로 감싸 잘랐다. 이스케이프 중첩으로 크기가 다시 증가하고, 구조화된 출처와 이어 읽기 위치가 가려졌다.

## 구현 변경

1. 알려진 모델은 기존 토크나이저를 사용한다. 미지원 모델은 `cl100k_base` 토큰 수에 25% 여유를 더해 추정한다. UI에서 공급자가 반환한 실제 사용량과 컨텍스트 추정을 구분한다. 기억 메타데이터 초과 오류에 계산량과 제한을 표시한다.
2. 일반 응답·도구 결과 외에 최대 세 번의 정리 요청 공간을 예약한다. 정리 요청에는 유지보수 도구만 제공하고, 도구 결과를 1,024 토큰 이내로 제한한다. 추론 모델의 출력 잘림을 피하기 위해 출력 한도는 일반 요청과 동일하게 예약한다. 마지막 메시지에 명시적인 체크포인트 제어 요청을 전달한다. 이 예약이 불가능한 설정은 명시적으로 거부한다.
3. 실제 전송 직전에만 정리 시도 횟수를 올린다. 전송하지 못한 요청은 횟수를 소모하지 않으며, 오류에 입력·출력·설정 한도를 표시한다.
4. 체크포인트 완료 호출은 같은 묶음의 다른 쓰기 뒤에서 평가한다. 다른 쓰기끼리의 순서는 유지하고, 실행 순서를 바꿔도 결과는 원래 호출 ID에 대응시킨다. 하나라도 실패하면 완료하지 않는다. 확인된 정리 대화도 활성 컨텍스트에서 제외하되 원문에는 보관한다. 완료 도구가 필수 `progress`와 선택적 `next`를 함께 저장하므로 진행 상태 갱신을 위한 별도 호출을 빠뜨리는 문제를 줄인다.
5. 도구 결과의 실제 메시지 직렬화 크기를 기준으로 제한한다. 본문은 구조 안에서 줄이고 출처와 이어 읽기 위치를 유지한다. 원문 아카이브를 재사용해 중첩 preview와 중복 아카이브를 방지한다.
6. 작은 결과 한도에서 원문 읽기 위치가 전진하지 않던 경우를 수정했다. 유지보수 중 제공하지 않는 소스 도구는 실행부에서도 거부한다.
7. 정수 필드에 모델이 보낸 숫자 문자열은 비어 있지 않은 ASCII 숫자로만 구성되고 정수 범위 안에 있을 때 정규화한다. 음수·소수·공백·지수 표기와 오버플로는 계속 거부한다.
8. 필요하면 가장 최근의 완료된 메시지 묶음도 정리 대상으로 선택한다. 준비 이후 추가된 미확인 구간은 제외하지 않으며, 원문 보관량을 안전하게 줄일 수 없으면 전체 변경을 취소한다.

## 자동 검증

- GLM 이름을 사용하는 한국어 기억 20건 저장 및 상시 목록 예산 검사.
- 실패한 저장 이후 세 번의 연속 체크포인트와 초기 제약·기억 재발견.
- 완료 호출이 저장보다 먼저 전달되어도 성공한 전체 묶음 뒤에 평가되는지 검사.
- 같은 묶음의 저장이 실패하면 원문이 제외되지 않는지 검사.
- 입력 초과 시 모델을 호출하지 않고 정리 횟수와 원문을 보존하는지 검사.
- 따옴표·역슬래시·한국어가 섞인 파일 결과의 출처, 크기, 이어 읽기 검사.
- 원문 전체 페이지 재조립 및 반복 잘림 시 아카이브 재사용 검사.
- 기존 세션·도구·SSE·브라우저·시작/종료 스크립트 테스트.

이번 수정의 Rust 자동 테스트 34개, 프런트엔드 설정·채팅 테스트 3개, 실행 스크립트 테스트 3개가 통과했다. 실제 공급자를 호출하는 2개 테스트는 일반 실행에서 제외한다. Clippy 경고 검사와 포맷 검사도 통과했다.

검증 명령: `npm test`, `npm run test:ui -w frontend`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, `git diff --check`.

## 실제 모델 검증

연결 설정의 `z-ai/glm-5.3-flash`, 컨텍스트 64,000, 모델 한도 설정 200,000을 사용한다. API 키와 대화·기억 원문은 이 보고서에 저장하지 않는다. 기존 실패 세션은 원래 서버의 RAM에 유지한다.

첫 수정본에서 기억 저장은 성공했지만, 정리 대화가 즉시 다음 체크포인트를 유발했고 완료 호출 순서 때문에 재시도 제한에 걸렸다. 이를 반영해 정리 대화 제외와 완료 호출의 묶음 마지막 평가를 추가했다.

실제 실행은 프로젝트 구조·주요 실행 흐름·오류 처리의 세 조사 항목을 대상으로 문서 작성과 대조 검증을 시도했다. 이는 장애 회귀 검증이며 동일 프롬프트 반복 품질 벤치마크나 OpenCode 비교 결과는 아니다. 명시적 opt-in 테스트는 유료 API 요청을 사용할 수 있으며 일반 `cargo test`에서는 실행되지 않는다.

### 실제 측정 결과

- 단일 체크포인트 프로토콜 테스트: 완료. 진행 요약 저장과 기억 재조회 후 답변까지 성공했다. 체크포인트 1회, 입력 11,389 / 출력 9,383 토큰, 약 212초.
- 중단된 읽기 전용 조사 세션을 RAM에서 복원한 테스트: 체크포인트 3회, 기억 8개, 입력 126,182 / 출력 22,165 토큰, 약 714초. 중간 기억 저장 실패 1건은 이후 수정되어 성공했다. 정리 후 기억 및 원문 재조회도 성공했다.
- 해당 실행에서 `context_limit`은 재발하지 않았다. 마지막 LLM 요청은 180초 제한의 `request_timeout`으로 중단됐다. 문서 파일은 생성되지 않았고 조사 항목 검증은 0/3이므로, 전체 문서 생성 완료를 요구하는 실제 테스트는 실패로 기록한다.
- 실제 조사 실행 이후, 체크포인트 호출 순서 변경 시 결과 호출 ID 대응을 수정했다. 이 수정은 호출 ID를 직접 확인하는 자동 회귀 테스트로 검증했으며, 이후 아래의 웹 세션 검증에도 사용했다.
- 브라우저 테스트 2개도 통과했다. 최신 실행 파일을 테스트 서버 3032에 적용했다. 기존 사용자 서버 3030과 세션은 변경하지 않았다.

실제 테스트 명령은 `MNEMOARC_LIVE_TEST=1 cargo test --test live_checkpoint configured_model_completes_checkpoint_with_inline_progress -- --ignored --nocapture`이다. 조사 재개 테스트는 여기에 `MNEMOARC_LIVE_SESSION`으로 로컬 읽기 전용 세션 API URL을 지정하고 `configured_model_resumes_readonly_investigation`을 선택한다. 재개 테스트는 이미 파일 쓰기를 수행한 세션을 거부한다. 조사 재개 테스트의 복원 상태는 테스트 프로세스 RAM에만 존재하며 종료 후 폐기된다.

### 후속: 실제 요약 파일 생성 및 최종 검증 성공

> 후속 확장 테스트에서 같은 결과 파일을 494줄 문서로 갱신했다. 아래 60줄·해시·완료 상태는 당시 실행의 기록이다. 최신 결과와 자동 검증 미완료 사항은 [확장 테스트 보고서](summary-expansion-validation.md)를 참고한다.

2026-09-19, 최신 서버 3032의 세션 `821e4685-a3da-49b3-ae6c-52d0840bb7d4`에서 같은 실제 모델로 수행했다. 원래 사용자 서버 3030은 변경하지 않았다. 새 세션은 RAM에 유지돼 UI에서 확인할 수 있다.

- 결과 파일: `/Users/iceblue/workspace/llm_agent_summary.md` — 60줄, 8,262바이트. 프로젝트 구조·주요 실행 흐름·오류 처리와 미확인 사항을 포함한다.
- 최종 실행 상태 `complete`, 오류 없음. 조사 항목 3/3이 `verified`이고 `final_check`는 `complete=true`, `incomplete=[]`, `review=1`을 반환했다.
- 체크포인트 12회, 기억 16개. 이번 세션에서 `context_limit`과 요청 시간 초과는 발생하지 않았다. 중간 도구 인자 오류와 기억 저장 실패는 복구했고, 한 번의 실행 토큰 예산 소진 후 같은 세션에서 검증을 이어갔다.
- 인용 32개, 서로 다른 출처 파일 6개를 대상으로 경로 존재와 줄 범위를 검사했다. 핵심 설명을 코드와 대조하고, 3개 문서 섹션 해시 및 연결된 출처 13개의 파일 해시 일치도 별도로 확인했다. 출력 API가 디스크 파일과 같은 내용을 잘림 없이 반환하는지 확인했다.
- 최종 파일 SHA-256: `ca2d0cc2ce3161ef36b780e9b9035da9889f12b1d03cf378bcf4f807ed2ee767`.

검증 조건은 기본값 그대로가 아니다. 해당 세션만 요청 제한을 360초로 늘렸고, 진행 중 추론 강도를 `low`, 컨텍스트 예산을 96,000으로 조정했다(설정된 모델 한도 200,000 이내). 64,000에서는 정리가 자주 발생해 기억을 읽고 다시 정리하는 비효율이 관찰됐다. 전역 설정은 바꾸지 않았다.

모델이 `document_edit`로 초안을 생성·보완했다. 검토자가 작성 우선순위와 잘못된 인용·도구 인자를 두 차례 지적했고, 마지막에는 소수 인용 범위·과도한 단정·누락된 행동 분기를 소스와 대조해 직접 교정했다. 모델은 그 수정본을 다시 읽고 최종 검증을 마쳤다. 따라서 무개입 자율 요약 품질을 입증한 결과로 해석하면 안 된다.

세션 누적 사용량은 입력 1,232,866 / 출력 56,306 토큰으로 표시됐다. 취소된 요청이 포함돼 `estimated=true`이며 공급자 청구 총량과 동일하다고 보장하지 않는다. 여러 차례 이어 실행한 세션 누적량이므로 한 번의 실행 예산 500,000과 구분한다. 결과 생성·검증에는 성공했지만 반복 읽기와 정리 비용은 여전히 개선 과제다. 대상 `llm_agent`의 DB 연결이나 런타임 동작 시험을 수행한 것은 아니다.

## 한계

미지원 모델의 토큰 수는 공급자 토크나이저와 정확히 일치하지 않는다. 25% 여유는 추정 여유이며 모든 모델의 과소 추정을 수학적으로 방지하는 상한은 아니다. 검증 실패·정리 실패 시 원문 보존과 복구 가능한 중단 정책은 유지한다.
