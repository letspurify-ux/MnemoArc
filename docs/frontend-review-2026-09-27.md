# 프론트엔드 리뷰와 수정 — 2026-09-27

## 범위와 결과

React 작업 공간, 채팅 전송, 실시간 상태 갱신, 대화 페이지 조회, 설정·프로젝트 편집, 기억·문서 패널, Markdown 링크를 검토했다. 화면의 동작을 Rust 웹 API의 요청 종류, revision, 페이지 커서, 원문 정리 규칙과 대조했다.

수정 전 기존 단위 테스트 5개와 브라우저 테스트 15개는 통과했다. 별도로 만든 브라우저 테스트에서 15가지 문제 상황이 실제로 실패하는 것을 확인했다. 관련 실패 처리와 세션 교체 검증도 추가해, 수정 후 단위 테스트 12개와 브라우저 테스트 35개가 모두 통과했다.

## 발견한 문제와 수정

| 우선순위 | 재현 조건과 영향 | 수정 |
| --- | --- | --- |
| 높음 | ‘기존 작업 질문’이 기본 선택된 화면에서 `계속`을 전송하면 `auto`로 요청했다. 서버는 이를 작업 재개로 해석하므로 질문 안내와 달리 작업을 실행할 수 있었다. | 표시된 `question` 또는 `chat`을 그대로 전송한다. 재개는 상단의 명시적인 동작을 사용한다. |
| 높음 | 작업 방식을 바꾸는 요청이 끝나기 전에 전송하면 이전 방식으로 실행할 수 있었다. | 변경 중 전송·재개·기억 정리를 잠그고 선택값을 즉시 표시한다. 실패하면 기존 선택값과 전송 가능 상태를 복원한다. 세션별 처리 상태는 상위 컴포넌트에서도 추적한다. |
| 높음 | 현재 세션이 목록에서 제거되어 다른 세션을 자동 선택할 때, 새 상세 응답을 기다리는 동안 이전 채팅을 표시했다. 전송 대상 ID와 화면의 세션이 달라질 수 있었다. | 선택 대상을 교체하는 즉시 이전 상세 화면을 해제한다. 상세 응답과 이전 대화 응답은 요청 당시의 세션 선택 순서도 확인한다. |
| 보통 | 현재 선택한 세션을 다시 누르면 채팅을 재생성해 미전송 입력이 사라졌다. | 같은 세션을 다시 선택하는 동작은 현재 채팅을 유지한다. |
| 보통 | 새 세션 요청을 보내자마자 편집 화면을 닫아, 생성 실패에도 프로젝트 초안이 사라졌다. 늦게 생성된 세션이 그 사이 이동한 설정 화면을 닫기도 했다. | 생성 성공 후 화면을 바꾼다. 그 사이 사용자가 이동했다면 선택을 덮어쓰지 않는다. 중복 생성과 대기 중 기존 입력창의 추가 편집도 막는다. 실패하면 기존 초안을 유지한다. |
| 보통 | 설정·프로젝트 저장을 기다리는 동안 다시 편집하면, 먼저 보낸 요청의 성공이 나중 편집까지 저장한 것으로 표시했다. 새로 입력한 API 키도 지웠다. | 편집마다 버전을 증가시켜 요청 당시와 같은 버전일 때만 미저장 표시와 키 입력을 초기화한다. 나중 편집이 남으면 이를 안내한다. 저장·연결 확인 중 적용 범위 전환을 막는다. |
| 보통 | 저장 중 화면을 떠나 새 설정 편집기를 열면, 이전 편집기의 성공 콜백이 새 화면의 이탈 확인까지 해제했다. | 편집기가 여전히 열려 있는지 확인한 뒤 상위 화면의 미저장 상태를 변경한다. |
| 보통 | 전체 설정 저장은 성공하고 세션 적용만 실패해도 일부 저장 사실을 알리지 않았다. 연결 확인 중 값을 바꿔도 현재 입력의 연결이 검증된 것처럼 표시했다. | 전체 저장과 세션 적용의 결과를 구분해 안내한다. 연결 확인 결과는 검사 당시 편집 버전과 함께 확인한다. |
| 보통 | JSON이 아닌 HTTP 200 응답을 성공으로 처리해 전송한 입력을 지우거나 저장 완료로 표시했다. | JSON 파싱 실패와 객체가 아닌 성공 응답을 오류로 처리한다. 실패한 전송의 초안은 유지한다. |
| 보통 | 이전 대화 조회 중 원문이 정리되면 늦은 페이지가 삭제된 대화를 화면에 되살렸다. 페이지 응답 순서에 따라 커서나 겹친 항목의 상태도 되돌아갈 수 있었다. | 원문 정리 경계는 항상 최댓값을 사용한다. 경계 이하의 항목은 모든 병합에서 제외하며 커서는 과거 방향으로만 이동한다. 겹친 항목은 새 revision을 따른다. 긴 갱신 공백으로 대화가 끊기면 최신 페이지의 커서를 유지해 빠진 부분을 다시 조회한다. |
| 보통 | 기억 A 다음 B를 선택했는데 A 응답이 늦으면 A가 표시됐다. 열린 기억이 수정·삭제돼도 이전 본문을 계속 표시했다. | 선택 ID와 기억 메타데이터를 기준으로 조회하고 이전 요청을 무효화한다. 개정·상태 변경 시 다시 읽고, 삭제되면 상세를 닫는다. |
| 보통 | 결과 문서 경로가 바뀌어도 이전 미리보기를 새 경로 아래에 표시했다. | 소스 폴더와 출력 경로가 바뀌면 미리보기와 진행 중 조회를 무효화한다. 문서 조회 중 중복 요청도 막는다. |
| 보통 | 오른쪽 프로젝트 편집은 미저장 상태를 추적하지 않아 패널 닫기나 화면 이동으로 입력이 사라졌다. | 저장 상태와 이탈 확인을 연결한다. 적용 요청 중 편집을 잠그고 성공 여부를 표시한다. 설정·프로젝트 초안에는 브라우저 이탈 확인도 적용한다. |
| 보통 | 숫자 입력을 비우면 즉시 `0`으로 바뀌었다. 소수 KiB·MiB는 소수 바이트로 전달돼 정수형 설정에서 거부될 수 있었다. | 빈 입력을 그대로 유지한다. DB 숫자 입력도 같은 변환을 사용하며 KiB·MiB는 가장 가까운 정수 바이트로 변환한다. |
| 보통 | 각주 클릭이 세션 ID를 보관하는 URL hash를 각주 ID로 바꿨다. 새로고침하면 선택했던 세션을 복원하지 못할 수 있었다. | 내부 링크는 URL을 바꾸지 않고 대상 요소로 스크롤·포커스한다. Markdown과 Mermaid에 같은 동작을 적용한다. |

## 설계 기준

- **요청 의도:** 화면에 표시한 선택을 그대로 API에 전달한다. 설정 변경이 완료되기 전에는 그 설정에 의존하는 실행을 시작하지 않는다.
- **초안 소유권:** 비동기 요청은 자신이 제출한 버전과 편집기에만 저장 완료를 적용한다. 초안은 React 메모리에 유지하며 브라우저 저장소에 키나 대화를 추가로 저장하지 않는다.
- **응답 순서:** 세션 선택 순서, 기억 선택, 문서 경로가 달라지면 이전 조회 결과를 적용하지 않는다. 사용자의 후속 이동은 이전 생성 요청보다 우선한다.
- **대화 보관 규칙:** `revision`과 `pruned_through`의 역할을 구분한다. 부분 페이지가 최신이어도 전체 실행 상태를 대체하지 않으며, 확인된 정리 경계는 이전 응답으로 되돌리지 않는다.
- **수정 범위:** 대화 병합과 내부 링크 처리는 작은 공통 함수로 분리했다. Rust API의 자동 모드 동작과 데이터 형식은 유지했다.

## 검증

| 명령 | 결과 |
| --- | --- |
| `npm test -w frontend` | 12개 통과 |
| `npm run build -w frontend` | 성공 |
| `cargo build` | 변경한 UI를 내장한 debug 실행 파일 빌드 성공 |
| `npm run test:ui -w frontend` | 기존 15개와 신규 20개, 총 35개 통과 |
| `git diff --check` | 통과 |

브라우저 회귀 테스트는 요청을 의도적으로 지연하거나 실패시켜 응답 순서를 제어한다. 신규 테스트에서는 브라우저의 처리되지 않은 JavaScript 오류도 검사한다. 원문 정리 병합, 커서, revision, 잘못된 API 응답, 숫자 단위 변환에는 별도의 단위 검증을 적용했다.

전체 브라우저 테스트로 설정 저장·연결 확인, 스트리밍 Markdown·표·수식·Mermaid, 세션 생성·전환·중지, 새로고침 복원, 완료 조건 검증, 문서 다운로드를 재검증했다. 데스크톱 작업 공간과 390px 모바일 설정·입력창의 캡처도 확인했다.

검증 환경은 macOS의 Chrome과 임시 설정으로 실행한 Rust 서버·로컬 LLM fixture다. 외부 모델 공급자와 실제 Oracle 연결은 사용하지 않았다. Vite의 기존 500kB 초과 청크 경고는 남아 있다.
