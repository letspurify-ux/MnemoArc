# Tree-sitter 심볼 검색과 호출·참조 추적

## 목적

문서 작성에 필요한 선언과 관련 코드를 찾는다. Rust 실행 파일에 포함된 Tree-sitter를 사용하며 별도 언어 서버, Node.js, JDK 또는 분석 대상 프로그램 실행이 필요하지 않다. 소스 본문 읽기와 문서 검증은 기존 도구를 계속 사용한다.

`symbol_search`와 `code_outline`은 같은 구문 분석·심볼 추출 코드를 사용한다. 지원 언어는 Rust, JavaScript/JSX, TypeScript/TSX, Python, Java, C#이다. 주석의 가짜 선언을 검색하지 않으며, 메서드·여러 줄 선언·중첩 선언·오버로드에 각각 위치와 심볼 ID를 제공한다.

TypeScript/TSX의 `namespace`·`module`도 모듈 선언으로 추출하며 자손의 `container`·`depth`와 읽기 ID를 유지한다. Rust `impl<T> Store<T>`의 이름과 멤버 컨테이너는 `Store`로 표시하고 전체 제네릭 선언은 시그니처와 원문에 보존한다.

## 사용 순서

1. `symbol_search`로 선언을 찾는다. 위치가 알려져 있으면 `path`, 여러 파일이면 `path_glob`으로 범위를 좁힌다.
2. 결과의 `path`와 `symbol_id`를 `symbol_relations`에 그대로 전달한다.
3. 관계 결과의 호출 위치는 `file_read`, 후보 구현은 `symbol_read`로 읽는다. 조건문·조기 반환·오류 경로도 함께 확인한다.
4. 읽은 근거로 문서를 작성하고 기존 조사 검증과 문서 검토를 수행한다.

```json
{"query":"handleRequest","match":"exact","path_glob":"src/**/*.ts","kind":"function"}
```

관계 조회 인자에서 `symbol_id`에는 실제 검색 결과 값을 사용한다.

| `symbol_relations.relation` | 결과 |
|---|---|
| `calls` (기본값) | 선택한 심볼 내부의 호출 위치와 대상 후보. 함수 조회는 중첩 함수·익명 콜백 내부를 제외하며, 클래스·모듈 조회는 자손 범위를 포함한다. |
| `callers` | 선택한 심볼로 연결되는 호출 위치. 후보·모호한 연결도 상태와 함께 반환한다. |
| `references` | 호출과 일반 참조 위치. 선언·import 문 자체·변수 바인딩 위치는 제외한다. |

익명 콜백 안에서 발견한 참조는 `enclosing_callable`에 위치와 `anonymous: true`를 표시한다. 선언으로 이름 붙은 호출 범위에는 `enclosing_symbol`도 제공한다.

C# 접근자·연산자·변환 연산자·소멸자와 식 본문 프로퍼티·인덱서도 이름 있는 호출 범위다. 그 안의 중첩 콜백 호출은 별도로 분리한다. Python 함수·람다의 기본 인자 표현식은 정의할 때 평가되므로 바깥 실행 범위의 호출로 기록한다. JavaScript 기본 인자는 해당 함수의 호출 범위에 남는다.

필드·상수·프로퍼티·이벤트 초기화 표현식의 호출은 해당 선언을 `enclosing_symbol`로 표시한다. 지역 클래스의 필드 초기화를 바깥 함수의 직접 호출에 포함하지 않으며 중첩 콜백은 별도 호출 범위를 유지한다. JavaScript의 계산된 필드 이름 표현식은 바깥 실행 범위에 남는다.

JS/TS 객체 축약 값(`{save}`)도 일반 참조에 포함한다. Rust 구조체 초기화·분해 패턴의 필드 이름은 같은 이름의 함수 참조로 세지 않는다. C#의 익명 `delegate` 본문은 별도 호출 범위로 다룬다.

Rust 매크로 호출과 매크로·어트리뷰트 토큰은 확장된 호출로 해석하지 않는다. 같은 이름의 매크로와 함수가 있으면 일반 함수 호출은 함수 후보만 반환한다. Java 어노테이션과 C# 어트리뷰트의 이름은 타입 참조로 분류한다. C#의 `[Save]`는 [언어 명세의 접미사 생략 규칙](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/attributes)에 따라 `SaveAttribute`도 후보로 찾으며, 둘 다 선언되어 있으면 후보를 함께 표시한다. `[@Save]`는 접미사를 붙이지 않고 정확한 타입 이름만 찾는다. 상속 관계는 검증하지 않는다.

Java·C#의 문장 레이블과 이동 대상, Python·C#의 이름 지정 인자 키, Java 어노테이션 인자 키, C# 어트리뷰트 인자 키와 튜플 타입 요소 이름은 같은 이름의 함수 참조로 세지 않는다. 인자 값과 C# `goto case`의 값 표현식은 참조로 유지한다.

## 검색과 페이지 계약

- `symbol_search.query`는 기본적으로 대소문자를 구분하지 않는 부분 일치다. `match: "exact"`, `case_sensitive`, `kind`, `container`, `max_depth`는 `code_outline`과 같은 의미다. `container`는 반환된 `qualified_name`을 복사한다.
- `symbol_search.path`는 파일 또는 폴더다. 폴더 지정 시 그 폴더로 이어지는 경로와 하위 폴더만 순회하며, 상위의 ignore 규칙과 기존 제외 규칙을 유지한다. 관계없는 폴더의 권한 오류가 지정 폴더의 검색을 막지 않는다. `path_glob`과 함께 사용할 수 없다. 기존 `pattern`은 `path_glob`의 별칭으로 유지한다.
- `symbol_relations.path_glob`은 조사할 프로젝트 파일을 제한한다. 선택한 심볼의 파일은 항상 포함한다. 범위 밖의 의존성 본문은 탐색하지 않는다. Rust 모듈 경로 계산에는 스캔 밖 `lib.rs`/`main.rs`의 존재 여부도 반영하며, 이 경로가 추가·삭제되면 관계 조회 커서를 만료시킨다.
- 두 도구는 기본 20개, 최대 100개씩 반환한다. `next_cursor`를 이어 사용할 때 필터와 대상은 유지한다. `limit`만 바꿀 수 있다.
- 파일 추가·삭제·내용 변경이나 필터 변경은 커서를 만료시킨다. 심볼 ID는 파일 경로·내용 해시·선언 범위에 연결돼 있으며 변경 후에는 새로 검색해야 한다.
- 최종 결과 토큰 예산이 작으면 완전한 항목 단위로 페이지를 줄인다. 한 항목도 들어가지 않으면 기존 원문 이력 보관·이어 읽기를 사용한다.
- `matched_files`는 경로 조건에 맞는 파일 수, `scanned_files`는 실제 분석한 지원 언어의 텍스트 파일 수다. `skipped_files`, `parse_error_count`, `parse_error_files`로 분석하지 못한 범위를 표시한다.

## 관계 상태

| `resolution` | 의미 |
|---|---|
| `resolved` | 현재 파일의 유일한 지역 선언에 구문상 연결됐고 관측된 가림·재할당이 없다. 실행 여부나 런타임 대상에 대한 보장은 아니다. |
| `candidate` | import, 모듈 경로, 소속 타입 등으로 후보 하나를 찾았다. 컴파일러나 모듈 로더로 확정한 결과가 아니다. |
| `ambiguous` | 같은 연결 근거에 여러 선언·오버로드가 해당한다. 인자 개수만으로 하나를 선택하지 않는다. |
| `unresolved` | 수신 객체 타입, 지역 바인딩, 외부 모듈, 구문 오류 등으로 대상을 연결하지 못했다. `reason`을 보고 추가 조사한다. |

이름만 같은 다른 파일의 함수를 연결하지 않는다. 매개변수·지역 변수·재할당·더 가까운 중첩 선언을 확인한다. 구조 분해의 키와 기본값 표현식은 바인딩에서 제외한다. 함수 범위를 사용하는 Python 바인딩과 JavaScript `var`, 반복문·catch·람다 매개변수, Rust 패턴, Python comprehension의 별도 범위도 고려한다. Rust·Java·C#·TypeScript/TSX의 제네릭 타입 매개변수는 바깥의 같은 이름 타입과 구분하며, 해당 매개변수의 실제 타입이나 정적 호출 대상은 확정하지 않는다. TypeScript의 타입 참조와 런타임 값 참조도 구분한다. Python `:=`, `del`, `match`의 캡처도 바인딩에 반영하며, 패턴의 키·타입 이름·점으로 연결된 속성값은 캡처로 취급하지 않는다.

중첩 블록이나 콜백에서 재할당한 이름은 해당 바인딩의 범위 전체에서 확정 연결하지 않는다. 실행 순서나 조건을 분석하지 않으므로 재할당이 실행되기 전의 호출도 미해결로 남을 수 있다. Python `global`/`nonlocal` 선언은 해당 함수 범위에서 보수적으로 미해결 처리한다. 실제 대입이 있으면 영향을 받는 모듈·바깥 함수 바인딩도 미해결로 처리하되, 더 가까운 지역 선언이 가리는 호출은 별도로 연결한다. JavaScript의 이름 있는 함수 표현식 내부 이름은 바인딩으로만 기록하며, 클래스 표현식 내부 이름은 그 표현식 안에서만 연결한다.

`++`·`--`도 재할당으로 반영한다. 단순 이름을 괄호로 감싼 `((target))()`는 호출로 유지하되 `(factory())()`와 같은 동적 함수값의 대상을 추측하지 않는다. Rust 제네릭 경로의 타입 인자는 이름 비교에서 제외하며 여러 특수화의 멤버가 일치하면 모호한 후보로 남긴다.

Python 함수 매개변수는 본문에서 사용하며 기본값 표현식은 바깥 범위에서 찾는다. 클래스 이름 공간은 클래스 본문과 메서드 기본값에서 사용하고, 메서드·중첩 클래스·comprehension 본문에서는 건너뛴다. comprehension의 첫 iterable 표현식은 바깥 범위를 사용한다. Rust `let`의 초기값과 `for`의 iterable, Java/C# foreach의 iterable에서도 새 반복·지역 변수가 바깥 이름을 가리지 않는다.

같은 `qualified_name`을 가진 지역 타입·모듈도 실제 선언 범위로 구분한다. 서로 다른 블록의 동명 멤버를 합치지 않는다. Rust 수명과 루프 레이블은 값 참조에서 제외하고, const 제네릭 매개변수는 자신의 선언 범위에서 바깥 값을 가린다. C# 인덱서 매개변수와 set/init/add/remove의 암시적 `value`도 해당 범위에만 적용한다.

언어별 연결은 다음 범위에서 후보를 제공한다.

- JS/TS: 상대 경로의 명시적 ESM import, 이름 별칭, namespace import, 직접 export와 같은 파일의 export 목록. 직접 export한 선언에 추가한 별칭과 문자열로 표기한 export 이름도 조회한다. `export default name`과 default 키워드 뒤의 줄바꿈·주석도 처리한다. 로컬 수출 목록의 원래 이름은 참조로 남기고 공개 별칭과 원격 재수출 이름은 지역 참조로 세지 않는다. import한 클래스의 멤버는 그 클래스 내부에서 찾는다. TypeScript의 `Types.Foo`는 한정자를 유지하며, `import type`, `export type`과 개별 `type` 표기는 타입 참조 후보에만 사용하고 런타임 호출 후보에는 사용하지 않는다. [TypeScript 모듈 문서](https://www.typescriptlang.org/docs/handbook/esm-node.html)를 따른다.
- Python: 프로젝트 루트 또는 상대 경로의 `import`/`from ... import ...`, 별칭과 클래스 멤버 후보. `import pkg.mod`의 `pkg.mod.member`, `from . import mod`의 하위 모듈 경로를 구분한다.
- Rust: `use`의 별칭·중첩 목록, `crate`/`self`/`super`와 명시적 모듈 경로, 현재 impl/trait의 `Self` 멤버. 상대 경로는 가까운 지역 타입·모듈이 바깥 선언을 가리는지 확인한다. `r#`가 붙은 식별자는 이름 비교에서 일반 표기와 같게 처리하며 원문 위치와 표현식은 유지한다. 타입 참조는 같은 이름의 값 바인딩과 구분한다. 중첩 모듈에 부모 모듈의 이름을 자동 상속하지 않는다. 파일 이름과 `lib.rs`/`main.rs`/`mod.rs` 배치에 따른 후보이므로 모듈 속성·Cargo 설정까지 확인한 결과는 아니다.
- Java: 명시적 타입·static 멤버 import, 같은 패키지 타입 후보. 같은 패키지의 다른 파일에 선언된 타입도 `new Store()` 후보에 포함한다. 단순 메서드 호출과 생성자의 타입 이름은 값 변수와 구분한다. 같은 이름의 매개변수나 필드가 `save()`를 가리지 않으며 `receiver.save()`의 수신 객체는 별도로 확인한다. [JLS 이름 가림 규칙](https://docs.oracle.com/javase/specs/jls/se25/html/jls-6.html#jls-6.4.1)을 따른다.
- C#: 타입 별칭, namespace `using`, `using static`, 같은 namespace 타입 후보. `new Store()`의 타입 이름은 같은 이름의 지역 값과 구분하며, `using` 또는 현재 namespace의 다른 파일에 선언된 타입도 후보에 포함한다. 중첩 클래스에서도 바깥 namespace를 사용한다. [C# 이름 공간 규칙](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/basic-concepts)을 따른다. `global using`의 다른 파일 전파는 분석하지 않는다.
- 현재 클래스의 수신자 멤버도 후보로 표시한다. `this`는 해당 언어에서만 적용한다. Python 메서드의 첫 매개변수와 Rust의 `self`는 재할당·가림을 확인하고, Python의 명시적 `staticmethod` 매개변수는 수신자로 취급하지 않는다. 상속·인터페이스·런타임 디스패치를 확정하지 않는다.

Rust 경로의 공백·주석은 이름 비교에서 제외한다. 함수 내부 모듈에서도 `self::`·`super::`는 실제 모듈 범위를 사용하고, `use`의 대상은 import 선언 위치에서 찾는다. `self::target()`과 `self.target()`은 구문 종류로 구분한다. C#의 `@` 식별자는 일반 이름과 비교하되 `@this`는 일반 변수로 남긴다. Python의 실제 수신자 매개변수는 같은 이름의 바깥 import보다 우선한다. 결과의 원문 표현식과 위치는 유지한다.

타입 추론, 패키지·경로 별칭 설정, wildcard import, 재수출 연쇄, Rust 매크로 확장, 리플렉션, 의존성 주입은 해결하지 않는다. Python 모듈 탐색 경로와 Rust 크레이트 구성 등 실행 환경에 따라 후보가 실제 대상과 다를 수 있다. 복합 수신 표현식과 함수값의 호출도 미해결로 남을 수 있다.

들어오는 호출·참조 조회는 선택한 심볼에 연결할 근거가 있는 항목만 반환한다. 미해결 대상을 제외하므로 빈 결과를 “호출자가 없다”는 근거로 사용하면 안 된다. `complete_call_graph`와 `semantic_verified`는 항상 `false`다.

## 근거·실행 경계

관계 결과는 위치·파일 해시·심볼 ID와 후보 사유를 제공하고 출처 ID를 생성하지 않는다. 검색과 구조 조회의 선언·시그니처 발췌는 기존 클라이언트를 위해 출처 ID를 유지하지만 구조 탐색 품질로 표시하며 완전한 줄을 읽었다는 검증에 사용하지 않는다. 500자 제한으로 선언 줄이나 시그니처 끝이 잘리면 `line_end_complete`를 `false`로 표시한다. 시그니처가 들여쓴 줄에서 시작하면 `line_start_complete`도 `false`다. 두 도구 모두 문서 읽기 커버리지를 늘리지 않는다.

경로 허용·제외·무시 규칙과 심볼릭 링크 제한을 적용한다. 도구 경로로 표현할 수 없는 UTF-8 이외의 파일명은 건너뛰고 `skipped_files`에 포함한다. 구문 캐시는 파일 해시와 언어에 연결되며 접근 권한과 관계 판정을 저장하지 않는다. 조회마다 현재 소스와 허용 경로를 확인한다.

한 번의 작업은 지원 파일 2,048개, 원문 합계 32MiB, 수집한 선언 100,000개, 참조 위치 200,000개로 제한한다. 공유 추출기의 파일당 선언 한도는 20,000개다. `symbol_search`는 필터를 먼저 적용하므로 전체 선언이 한도를 넘는 파일에서도 좁힌 검색은 가능하다. 관계 조회는 모든 선언을 수집하므로 이 한도가 그대로 적용된다. 구문 트리의 실제 메모리 크기 제한은 아니다. 초과하면 부분 결과를 완전한 결과로 반환하지 않고 범위를 좁히도록 안내한다. 파일 목록을 순회하는 단계부터 설정된 도구 시간 제한과 취소를 적용한다.

새 세션에서 두 도구를 기본 제공한다. 체크포인트와 문서 마감·집중 복구에서는 기존 탐색 도구와 같은 제한을 적용한다. 기존 세션에서는 도구 선택으로 활성화할 수 있다.

## 검증

`tests/navigation.rs`는 실제 구문 분석기와 임시 프로젝트로 다국어 선언, 별칭, 가림, 중첩 콜백, 오버로드, 미해결 대상, 인바운드 참조, 변경 감지, 경로 제한, 구문 오류, Unicode 위치와 결과 예산의 이어 읽기를 검사한다. 기존 구조·문서 도구 테스트도 함께 실행한다.

`tests/symbol_regressions.rs`는 2026-09-30에 수정한 9개 결함과 인접한 경계 조건을 검사한다. 한정된 TypeScript 타입의 오연결, 언어별 수신자·재할당, 가까운 Rust 타입·모듈, 초기값 없는 선언과 enum 참조, 복수 선언의 읽기 범위, 추가 export 별칭, Java compact constructor의 호출 소유자, C# 파일 범위 namespace의 하위 호출, Rust raw identifier를 포함한다. 선언과 이름 노드의 바이트 범위가 같아도 선언 종류를 함께 확인해 참조가 누락되지 않도록 한다.

`tests/symbol_review_followup.rs`는 후속 검토의 회귀·경계 테스트 33개다. 기본 인자의 호출 소유자, 동명 컨테이너의 실제 범위, Rust 수명·레이블·const 매개변수·지역 모듈·import 위치, C# 호출 범위·인덱서·암시적 매개변수·`@` 식별자, 문자열 export 이름을 검사한다. 한정된 타입 참조를 값 바인딩과 구분하고 Rust `impl` 블록을 타입·값 참조 대상으로 삼지 않는지도 확인한다. 검색 결과에서 같은 표시 경로의 ID가 구분되는지, 읽기가 다른 심볼 범위를 거부하는지, 6개 언어의 불완전한 소스에서도 검색·읽기 범위를 유지하는지도 확인한다.

`tests/symbol_precision.rs`는 추가 정밀 검토에서 발견한 6개 결함과 경계 조건을 검사한다. 완료된 심볼 읽기의 범위 밖 `next_line`, 증감 연산 뒤의 확정 연결, 괄호 호출 누락, 제네릭 Rust impl·경로 연결 누락, 지역 클래스 초기화의 호출 소유자, TypeScript namespace·module 누락을 다룬다. 멤버 후보·특수화의 모호함·더 가까운 이름 가림·콜백 분리도 검사한다. `symbol_read.next_line`은 심볼 내부에 요청하지 않은 줄이 남았거나 요청 범위가 잘렸을 때만 제공하며, 심볼 끝까지 읽으면 `null`이다.

정밀 검토에서 추가한 회귀 검사는 다음 오류를 재현하고 수정 여부를 확인한다.

- 구조 분해·반복문·catch·람다·패턴 바인딩과 중첩 블록의 재할당을 놓쳐 바깥 함수를 잘못 연결하는 경우.
- Python 점 경로 import와 상대 하위 모듈을 혼동하는 경우, JS default export를 놓치는 경우, Rust 부모 모듈 이름과 `Self` 경로를 잘못 처리하는 경우.
- 20,000개가 넘는 선언 중 정확한 이름 검색이 실패하는 경우, Unix 파일명의 실제 백슬래시를 경로 구분자로 바꾸는 경우, 구문 오류 후보를 제외한 뒤 관계 상태와 후보 수가 일치하지 않는 경우.
- Python 클래스·함수 기본값·comprehension의 범위를 혼동하는 경우, Rust 초기값을 새 바인딩으로 가리는 경우, Java 값 이름을 메서드·생성 타입 이름과 혼동하는 경우.
- JS 객체 축약 참조를 놓치는 경우, Rust 필드 이름을 함수 참조로 세는 경우, C# 익명 delegate의 호출을 바깥 함수에 포함하는 경우.
- 지정 폴더 밖의 권한 오류로 검색이 실패하는 경우, 긴 선언 발췌를 완전한 줄로 표시하는 경우. 폴더 범위를 좁혀도 상위 ignore 규칙이 유지되며 만료된 시간 제한으로 탐색을 시작하지 않는지도 검사한다.
- Rust·Java·C# 타입 참조와 C# 생성자 타입을 같은 이름의 지역 값 때문에 놓치는 경우. 제네릭 타입 매개변수의 선언·참조·정적 호출을 바깥 타입에 잘못 연결하는 경우. C# `using`/현재 namespace와 Java 같은 패키지의 다른 파일에 있는 생성자 타입을 놓치는 경우. 구조 조회에서 잘린 선언·시그니처를 완전한 줄로 표시하는 경우.
- TypeScript/TSX 제네릭 타입 매개변수를 바깥 타입 별칭에 연결하거나 타입 참조를 같은 이름의 값 때문에 놓치는 경우. Rust 진입 파일이 `path_glob` 밖에 있을 때 스캔된 모듈 사이의 `crate::` 호출을 놓치고, 진입 파일의 삭제 뒤에도 이전 관계 커서를 받아들이는 경우.
- Python 한 함수의 `global`/`nonlocal` 선언을 다른 함수에 잘못 적용하는 경우, 실제 대입으로 바뀐 바깥 바인딩을 확정하는 경우, 별도의 지역 선언까지 미해결로 처리하는 경우. Linux에서 UTF-8이 아닌 파일명 때문에 전체 검색이 실패하는 경우.
- Java·C# 문장 레이블과 `break`/`continue`/`goto` 대상, 이름 지정 인자·어노테이션·어트리뷰트의 키, C# 튜플 타입 요소 이름을 같은 이름의 메서드 참조로 잘못 세는 경우. 실제 호출과 인자 값, `goto case` 값은 유지하는지도 검사한다.
- JS/TS 로컬 수출 별칭과 원격 재수출 이름을 지역 함수 참조로 세는 경우. TypeScript의 타입 전용 수입·수출을 런타임 생성자 후보로 표시하거나 타입 참조에서 누락하는 경우.
- Rust 매크로 호출·인자·어트리뷰트 토큰을 같은 이름의 함수 호출이나 참조로 세는 경우. Java 어노테이션과 C# 어트리뷰트의 이름을 같은 이름의 메서드에 연결하거나, C#의 생략된 `Attribute` 접미사 때문에 타입 참조를 놓치는 경우. `[@Save]`처럼 `@`를 쓴 이름에 접미사를 붙이거나 타입 참조를 놓치는 경우.

실제 모델의 문서 정확도나 토큰 절감률은 별도 전후 평가가 필요하다. 이 구현은 LLM이 실행 흐름을 올바르게 해석했다는 보증을 추가하지 않는다.
