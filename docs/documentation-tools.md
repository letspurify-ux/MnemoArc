# 문서 조사·작성 도구 개선

## 제공 기능

`source-docs` 선택 시 기존 도구와 함께 다음 기능을 사용할 수 있다.

| 도구 | 사용법과 보장 |
|---|---|
| `file_read` | 전체 줄 수·파일 해시와 `content.line_start`, `content.line_offsets`를 제공한다. `line_offsets`는 반환 텍스트 내 Unicode 문자 위치이며 각 줄의 시작을 가리킨다. 본문을 잘라도 이어 읽기 위치와 줄 지도를 함께 갱신한다. |
| `document_inspect` | 인자 없이 출력 파일의 해시·실제 줄 수·목차를 조회한다. `section`에 제목을 주면 해당 섹션만 읽고 섹션 해시를 반환한다. `offset`으로 이어 읽을 때는 첫 페이지의 `hash`를 `expected_hash`로 전달해야 하며, 중간에 파일이 바뀌면 거부한다. |
| `document_edit`의 `section` | `section`, `text`, `expected_hash`, `expected_section_hash`를 받아 해당 제목부터 다음 동급/상위 제목 전까지 교체한다. 원래 제목을 유지해야 한다. 코드 펜스 안의 제목은 무시하며 중복 제목과 외부 편집 충돌을 거부한다. 기존 원자적 파일 교체와 경로 제한을 적용한다. |
| `document_audit` | `path.ext:10-20` 및 Markdown 링크의 `path.ext#L10-L20` 출처를 검사한다. 코드 펜스 안의 예시는 인용 검사에서 제외한다. 파일 존재·허용 경로·줄 범위·연결된 소스 변경·문서 섹션·미검증 조사 항목을 한 번에 점검한다. 오류 목록은 페이지 조회 가능하다. |
| `investigation`의 `verify_batch` | `items`에 조사 항목 ID를 키로 하고 `{source_ids: [...], verification_note: "비교 내용"}`을 값으로 전달한다. 최대 20개를 순차 검증하며 항목별 성공/실패를 반환한다. 성공한 항목은 유지하고 실패한 항목은 재시도한다. |
| `symbol_search` | `query`, 파일 glob `pattern`, `cursor`, `limit`으로 JS/TS·Rust·Python 선언을 검색한다. 이름·위치·선언 줄·프로그램 발급 출처를 반환한다. 파일 변경 시 커서는 만료된다. |

일괄 검증은 관련 원문과 실제 문서를 비교한 뒤 호출해야 한다. 단순히 읽은 항목을 자동으로 검증 처리하지 않는다. `upsert`에서 생략한 출처·기억 참조·섹션은 기존 값을 유지하며 같은 제목의 중복 항목 생성을 거부한다.

## 실행 제어와 UI 설정

`모든 설정 → 실행과 예산`에서 다음 값을 편집할 수 있다. 기본 설정·저장 설정·세션 설정에 동일하게 적용된다.

- 작성·검증 예산 비율: 기본 50%. 실행 토큰 또는 시간 예산이 이 비율 이하로 남으면 조사 결과를 문서로 작성하는 단계로 전환한다.
- 검증 예산 비율: 기본 25%. 기존 미검증 항목을 우선하며 새 조사 항목 추가·전체 파일 목록·빈 쿼리 심볼 탐색을 제한한다. 필요한 특정 소스 읽기·검색·문서 수정은 허용한다.
- 동일 범위 반복 조회 제한: 기본 2회. 활성 대화에 동일 파일 해시·줄 범위·문자 오프셋의 결과가 이미 이 횟수 이상 있으면 본문을 재전송하지 않는다. `force_read=true`로 의도적인 재검증을 할 수 있다. 파일 변경이나 컨텍스트 제외 후에는 다시 읽을 수 있다.
- 반복 작업 중단 횟수: 기본 8회. 동일 조회 또는 동일 실패 호출이 문서 작성·검증 진전 없이 반복되면 `repeated_work_limit`으로 복구 가능한 중단을 한다. 호출 결과·문서·세션을 보존한다. 새 실행에서 카운터를 초기화한다.

작성 비율은 검증 비율보다 커야 하며 두 비율은 0과 1 사이여야 한다. UI에서는 퍼센트로 입력한다. 남은 예산과 단계·미검증 항목 수는 진행 패널 및 매 LLM 요청의 현재 상태에 포함된다. 비율은 단계 전환 기준이며 토큰을 별도 계정에 적립하는 방식은 아니다. 모델이 모든 검증을 예산 안에 끝낸다고 보장하지 않는다.

미완료 항목이 있을 때 `final_check`는 우선 처리할 항목을 반환하고 문서 검토 횟수를 소모하지 않는다. 항목이 모두 검증됐더라도 구조적 출처 검사가 실패하면 완료로 처리하지 않는다. 모델이 도구 호출 없이 종료하더라도 실행부에서 같은 검사를 수행한다. 실패하면 남은 예산 안에서 최대 2회(문서 검토 한도가 더 작으면 그 값) 검증으로 되돌리고, 끝내 해결하지 못하면 `partial` 상태로 남긴다.

## 권장 작업 순서

1. 심볼·경로 검색으로 범위를 좁히고 필요한 소스 줄만 읽는다.
2. 조사 항목을 만들고 확인한 내용부터 섹션으로 작성한다.
3. 출력 파일 해시나 줄 수는 `document_inspect`로 얻는다. 전체 파일을 다시 읽지 않는다.
4. 오류는 해당 섹션 원문을 수정한다. 문서 끝에 정정 설명을 덧붙이지 않는다.
5. `document_audit`의 미검증 항목과 오류를 처리하고 `verify_batch`로 비교 결과를 기록한다.
6. `final_check` 결과에 따라 완료 또는 미확인 사항을 명시한다.

## 확인한 범위와 한계

모의 LLM과 작은 로컬 fixture로 단계 전환, 반복 중단, 출처 검사, 부분 실패, 한글 문서 이어 읽기, 충돌·범위 제한을 회귀 검증한다. 브라우저 테스트는 외부 API 대신 로컬 SSE 서버를 사용한다. 실제 사용자 서버와 RAM 세션은 재시작하지 않는다.

심볼 검색은 정규식 기반 선언 탐색이며 LSP·AST·호출 그래프가 아니다. 메서드나 여러 줄 선언을 놓칠 수 있고 상수 선언도 포함한다. 문서 제목은 ATX 형식(`# 제목`)을 지원한다. 출처 검사는 지원 표기법의 경로·줄 범위·최신성을 확인할 뿐 모든 설명과 API 예제의 의미를 증명하지 않는다. 이번 변경은 이전 실제 모델 테스트의 실패를 회귀 검증한 것이며, 동일 실제 모델을 통한 500줄 요약 품질·비용 개선 측정은 별도 평가가 필요하다.

## 이번 변경의 검증 결과 (2026-09-19)

- Rust 자동 테스트 45개 통과, 외부 유료 모델 테스트 2개는 실행하지 않음.
- 프런트엔드 설정·채팅 테스트 3개, 실행 스크립트 테스트 3개 통과.
- 실제 Rust API와 로컬 SSE 서버를 사용하는 브라우저 테스트 2개 통과. 새 비율·반복 제한 네 가지의 UI 저장과 새 도구 표시를 확인함.
- Clippy 경고 검사, Rust 포맷 검사, diff 공백 검사 통과.
- 긴 한글 문서의 분할·복원, 파일 변경 후 재조회, 부분 검증 재시도, 잘못된 인용의 완료 거부, 조기 종료의 제한된 재시도, 반복 작업 중단 및 예산 단계 전환을 포함함.
