# 소스 탐색 효율 개선 (2026-09-20)

## 변경

- 새 세션에서 `source_search`, `code_outline`, `symbol_read`를 기본 제공한다. 기존 `file_list`, `file_read`, `document_inspect`도 유지한다. 사용자가 저장한 기존 세션의 도구 선택은 바꾸지 않는다.
- 특정 소스 질문에서는 파일 앞부분을 일괄 읽기 전에 알려진 식별자·경로를 검색하고, 필요한 구현 범위만 읽도록 공통 지침과 매 요청의 진행 안내를 보강했다. 독립 검색은 같은 호출 묶음으로 요청하도록 안내한다. 일반 문서 요약은 문서를 바로 읽는다.
- JSON 요청에서는 식별자 필드에 설명을 붙이지 않고, 실행 순서 근거의 양쪽 위치를 citations 배열에 넣도록 안내한다.
- Tree-sitter 구문 트리는 언어와 현재 내용 해시로 재사용한다. 매번 허용 경로와 실제 파일 내용을 확인하며, 필터·출처·읽기 범위는 각 호출에서 새로 계산한다. 최대 8개, 원문 크기 합계 4MiB까지 보관하며 큰 파일은 캐시하지 않는다. 이는 구문 트리의 정확한 메모리 사용량 제한은 아니다.
- 검색 페이지의 재스캔은 파일 추가·삭제·변경을 감지하는 기존 계약을 유지하기 위해 남겼다. 검색 결과 캐시나 읽기 I/O 제거까지 구현한 것은 아니다.

## 평가 방식

`tests/navigation_eval.rs`는 탐색 도구를 미리 지정하지 않고 실제 새 세션의 기본 도구로 시작한다. 정답·인용·전달된 구현 근거를 검증하며 아래 효율 상한도 검사한다.

| 사례 | 도구 호출 상한 | 누적 입력 토큰 상한 |
|---|---:|---:|
| 취소 의미 | 8 | 65,000 |
| 빈 검색 복구 | 4 | 35,000 |
| Java 구조 탐색 | 8 | 40,000 |

복구 사례에서 주입한 최초 실패 검색은 호출 수에서 제외한다. 커서 이어 읽기를 제외한 `file_read`에는 시작 줄과 줄 수가 명시돼야 한다. 이 기준은 준비된 특정 소스 질문에만 적용하며 일반 파일 읽기 API를 제한하지 않는다. 상한은 최적 성능이 아니라 저장된 모델 설정을 위한 회귀 경계다. 모델이나 질문을 바꾸면 기준을 재검토해야 한다. 경과 시간도 보고서에 저장하지만 공급자·네트워크 편차가 있어 합격 기준으로 쓰지 않는다.

## 검증 기록

검토 당시 취소 의미는 6회/47,959 입력 토큰, 검색 복구는 3회/27,327 입력 토큰이었다. 전자는 JSON 인용 누락, 후자는 식별자에 설명을 붙인 형식 오류로 평가에 실패했다.

첫 개선본의 취소 의미 2회에서는 각각 6회/49,645 토큰과 7회/80,071 토큰을 사용했다. 두 실행 모두 범위 없는 첫 페이지 읽기가 남았고, 두 번째는 입력 토큰 상한도 초과했다. 새 검사가 이를 탐지한 뒤 매 요청 진행 안내에 검색 우선·독립 호출 묶기를 추가했다. 이 중간 결과를 개선 성공으로 집계하지 않는다.

## 최종 재실행 결과

매 요청 진행 안내까지 반영한 최종 코드로 등록된 `llm_agent`의 두 사례를 각각 두 번 실행했다. 모델은 저장된 `z-ai/glm-5.3-flash`, 도구 설정은 새 세션 기본값이다. 소스와 기존 결과 문서 쓰기는 없었다.

| 사례 | 호출 수 | 입력 토큰 | 판정 |
|---|---:|---:|---|
| 취소 의미 1 | 5 | 47,556 | incorrect_or_missing:always_new_abort_error |
| 취소 의미 2 | 7 | 58,672 | missing_fact_citation:backend/src/server.js:210 |
| 검색 복구 1 | 4 | 37,991 | navigation_input_budget:37991>35000, tool_errors |
| 검색 복구 2 | 3 | 30,059 | 통과 |

최종 네 실행에서 범위 없는 첫 페이지 읽기는 없었다. 취소 의미 두 실행은 효율 기준을 모두 통과했지만, 첫 실행은 기존 Error 재전파를 인정하면서 항상 새 AbortError를 만든다고 답하는 모순이 있었고 두 번째는 응답 쓰기 위치의 JSON 인용이 빠졌다. 검색 복구 첫 실행은 `.on(`을 regex로 요청해 오류가 난 뒤 복구하면서 입력 토큰 상한을 넘었다. 두 번째는 모든 기준을 통과했다. 따라서 실제 모델 평가 전체는 실패이며, 안정적인 비용 감소나 의미 정확도 향상을 입증한 것으로 해석하지 않는다. 단일 모델의 소수 실행이다.

일반 테스트는 136개 통과, 유료 테스트 3개는 기본 실행에서 제외됐다. Clippy(`--all-targets -- -D warnings`), 포맷 검사, 릴리스 빌드도 통과했다. 파일 변경·언어별 캐시 분리·보관 상한과 기존 심볼/커서 무효화 검사를 포함한다. 마지막 효율 판정기 수정 후 해당 테스트도 재실행했다.

남은 작업은 실제 모델의 조건 해석·인용 누락·불필요한 regex 사용을 줄이는 것이다. 성능 상한을 완화하거나 정답 검사를 제거해 실패를 숨기지 않았다. 새 캐시의 지연 시간 개선율은 별도로 측정하지 않았다.

원시 실행 보고서: `/tmp/mnemoarc-navigation-final-20260920.json` (최종), `/tmp/mnemoarc-navigation-improved-20260920.json` (중간 단계, Java 포함). 재실행 방법은 [탐색 회귀 평가](navigation-regression-tests.md#재실행)를 따른다.

## 후속 설계

문자 OR 검색, 동일 모델 1회 검토, 명시적 JSON 인용 검사와 추가 반복 평가는 [소스 답변 검토 설계 및 결과](source-answer-review.md)에 기록했다. 후속 관측은 준비된 정답·인용 8/8, 효율 기준 포함 7/8이며 남은 비용 초과도 그대로 기록했다.
