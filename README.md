# MnemoArc

세션 안에서 기억을 저장·검색·재사용하며 소스 코드를 조사하고 근거 있는 Markdown 문서를 만드는 Rust 단일 에이전트입니다. Tokio 실행부, Ratatui TUI, OpenAI 호환 Chat Completions 클라이언트를 한 Cargo 패키지로 제공합니다.

## 시작하기

Rust 2024 edition을 지원하는 도구 체인이 필요합니다. 개발·검증 환경은 Rust 1.93.1입니다.

```sh
cargo build --release
cargo run -- config > config.toml
```

`config.toml`의 `model`과 `model_context`를 사용할 서버·모델에 맞춰 설정하세요. `model_context`는 입력과 출력을 합친 한도입니다. 초기 요청 예산은 64,000이며 모델 한도보다 클 수 없습니다. 모델 이름이나 서버의 한도를 자동으로 추측하지 않습니다.

```toml
base_url = "https://api.openai.com/v1"
model = "YOUR_MODEL"
model_context = 128000 # 실제 공급자가 제공하는 한도로 변경
api_key_env = "OPENAI_API_KEY"
context_tokens = 64000
output_tokens = 8000

[[projects]]
name = "my-project"
root = "/absolute/path/to/project"
output = "docs/source-summary.md"
include = []
exclude = ["secrets/**", ".env*"]
purpose = "진입점, 주요 흐름, 자료 구조와 오류 처리를 소스 근거와 함께 설명"
audience = "신규 개발자"
```

인증은 지정한 환경변수에서 읽습니다. 로컬 `.env`도 지원합니다. 키가 없는 로컬 서버에서는 인증 헤더를 생략합니다. 설정에 인증값을 직접 저장하지 않습니다.

```sh
export OPENAI_API_KEY='your-key'
cargo run -- check
cargo run
```

`check`는 일반 응답, SSE 스트리밍, 도구 호출과 대응 결과 왕복을 실제 요청으로 확인합니다. 연결 프로필을 여러 개 쓰려면 서로 다른 TOML 파일을 만들고 `--config profile.toml`로 선택합니다. 서버가 구형 출력 한도 필드를 요구하면 `legacy_max_tokens = true`, 스트림 사용량 옵션을 지원하지 않으면 `stream_usage = false`로 설정합니다.

TUI에 다음처럼 입력하면 조사를 시작합니다.

> 이 프로젝트를 신규 개발자에게 설명해줘. 진입점, 주요 실행 흐름, 핵심 데이터 구조, 오류 처리를 조사하고 소스 경로와 줄 근거를 포함한 문서를 만들어줘. 미확인 사항도 구분해줘.

같은 실행부를 UI 없이 사용할 수도 있습니다.

```sh
cargo run -- run --project /path/to/project --output docs/source-summary.md \
  --prompt '프로젝트 구조와 주요 흐름을 근거와 함께 문서화하고 검증해줘'
```

부분 완료·복구 가능한 중단은 종료 코드 2로 표시합니다. 취소하거나 프로그램을 종료해도 이미 작성한 결과 파일은 남습니다.

## TUI 사용법

왼쪽은 프로젝트별 세션, 중앙은 대화, 오른쪽은 상세 정보입니다. 보고 있는 세션과 실행 중인 세션은 별개이며 한 번에 하나의 에이전트만 실행합니다.

| 입력 | 동작 |
|---|---|
| 일반 텍스트 + Enter | 선택한 세션에서 작업 시작 |
| Shift+Tab | 세션 전환 |
| Tab | 목표 / 기억 / 도구·조사 / 사용량 / 설정 패널 전환 |
| PageUp / PageDown | 내용 스크롤 |
| Esc | 실행 취소, 세션 보존 |
| Ctrl+Q | 실행 정리 후 종료 |
| `/project /absolute/path` | 프로젝트 등록·선택 |
| `/new [번호]` | 프로젝트의 새 세션 생성 |
| `/close` | 현재 세션 종료·RAM 폐기 |
| `/resume` | 보존된 상태에서 재개 |
| `/cleanup` | 기억 체크포인트 요청 |
| `/memory [ID 또는 키]` | 기억 목록 또는 본문 표시 |
| `/settings` | 전체 설정 표시 |
| `/set KEY JSON` | 기본 설정과 현재 세션 설정 변경 |
| `/temp KEY JSON` | 현재 세션에만 임시 설정 적용 |
| `/project-set KEY JSON` | 현재 프로젝트 설정 편집 |
| `/output docs/summary.md` | 허용되는 결과 문서 경로 설정 |
| `/save` | 기본 설정과 프로젝트를 TOML로 저장 |
| `/check` | 연결 검사 |
| `/help` | 명령 안내 |

예: `/set model "YOUR_MODEL"`, `/set model_context 128000`, `/temp run_tokens 100000`, `/project-set exclude ["secrets/**"]`.

설정 우선순위는 기본값 → `.env`/프로세스의 `MNEMOARC_*` → 저장된 TOML → 세션 임시 설정입니다. 환경변수 값은 JSON으로 해석하며 일반 문자열도 허용합니다. 진행 중인 요청은 시작 당시 설정을 사용합니다. 한도를 낮춰 현재 상태가 들어가지 않으면 설정을 보류하고 정리 후 적용합니다. 인증 패널에는 환경변수 이름만 표시합니다.

## 기억과 컨텍스트

- **상시 상태:** 목표·제약·진행, 참조 기억, 최신 20개와 관련 최대 5개의 메타데이터를 매 요청에 제공합니다. 과거 상태 묶음을 누적하지 않습니다.
- **개별 기억:** 키/ID, 본문, 태그, 개정 번호, 종류·상태와 프로그램이 발급한 출처를 RAM에 저장합니다. 조회는 최신순을 바꾸지 않습니다. 선형 키워드 검색은 한국어 부분 문자열과 코드 식별자를 지원합니다.
- **원문:** 완료된 메시지·도구 묶음을 RAM에 보관하고 필요할 때 다시 검색·조회합니다. 컨텍스트 제외와 원문 폐기는 별개입니다.

기억은 같은 키를 갱신할 때 기존 개정 번호가 필요합니다. 참조 중인 기억은 해제하거나 원자적으로 교체해야 삭제할 수 있습니다. 목록 커서는 변경 시 만료됩니다. 용량 초과는 삭제 후보와 오류로 알리며 임의로 기억을 버리지 않습니다.

입력 예산의 80%에서 체크포인트를 준비하고 60% 이하를 목표로 합니다. 기억·상태 저장 또는 저장 불필요 사유를 확인한 뒤 지정된 완결 묶음만 제외합니다. 저장 실패·잘못된 인자·취소 시에는 제외하지 않습니다. 정리 요청 3회로 해결되지 않으면 세션을 보존한 채 중단합니다. 원문 폐기는 검토되고 이미 제외된 구간에만 적용합니다.

알려진 모델은 `tiktoken-rs` 토크나이저를 사용합니다. 알 수 없는 모델 이름은 UTF-8 바이트 수로 보수적으로 추정하며 UI에 추정 여부를 표시합니다. 메타데이터는 항목당 160 토큰 이내여야 하므로 미지원 모델에서는 제목·설명을 더 짧게 작성해야 할 수 있습니다. 서버가 제공하지 않은 사용량·캐시 사용량은 0으로 취급하지 않습니다.

## 파일 조사와 검증

`source-docs`를 선택하면 파일 목록, 경로·정규식 검색, 줄 범위 읽기, 문서 작성·추가·정확 부분 교체, 조사 목록 도구가 활성화됩니다. 선택 변경은 현재 호출 묶음 뒤에 적용합니다. 읽기만 최대 4개 병렬이며 상태 변경·쓰기는 순서대로 실행합니다.

읽기는 프로젝트 루트와 포함·제외 규칙을 따릅니다. VCS 내부, 빌드 산출물, 의존성 디렉터리, 바이너리·비 UTF-8·16MiB 초과 파일은 기본 조사 대상에서 제외합니다. 심볼릭 링크를 따라 프로젝트 밖으로 나갈 수 없습니다. 검색 결과는 페이지 커서로 이어 읽으며 변경 시 커서가 만료됩니다.

쓰기는 지정한 **한 결과 문서 경로**에만 허용합니다. 기존 파일의 해시와 부분 교체 대상의 유일성을 확인하고 임시 파일을 동기화한 뒤 교체합니다. 호출 ID별 성공 결과를 보존하여 같은 호출을 재실행하지 않습니다. 일반 소스 수정과 셸 실행 도구는 제공하지 않습니다.

조사 항목은 미조사 → 조사 중 → 작성됨 → 검증됨으로 진행합니다. 기억 개정, 소스 해시·줄·관찰 시각, 문서 섹션 해시를 연결합니다. 소스나 해당 섹션이 바뀌면 재검증이 필요합니다. `검증됨`은 에이전트가 원문 대조 기록을 남겼고 해시가 유효하다는 뜻이며 사실 정확성 자체를 자동 증명하는 점수는 아닙니다.

## 구조와 보관 범위

| 모듈 | 책임 |
|---|---|
| `agent` | 단일 실행 소유자, 예산·취소, 도구 순서, 안전 경계 설정 적용 |
| `session` | 세션별 상태, 원문, 조사 목록, 호출 결과 기록 |
| `memory` | 개정 기반 CRUD, 검색, 원자적 교체, 용량 검사 |
| `context` | 요청 구성, 토큰 계산, 체크포인트 준비·확인·제외 |
| `tools` | 정적 레지스트리, 입력·권한 검사, 파일·문서·기억 도구 |
| `llm` | OpenAI 호환 SSE, 호출 인자 조립, 사용량·재시도 |
| `ui` / `config` | TUI 명령·스냅샷, 검증·환경변수·TOML |
| `evaluation` | 고정 소스 반복 실행과 집계 결과 |

기억·대화·출처·호출 결과는 디스크 로그나 DB에 쓰지 않습니다. 세션 종료·프로그램 종료 시 사라집니다. 프로젝트 설정과 결과 문서는 남습니다. 평가 명령은 명시적으로 요청한 평가 결과 문서와 집계 JSON도 저장합니다.

용량은 직렬화된 논리 데이터 크기로 계산하며 프로세스 전체 RSS 한도는 아닙니다. 취소 시 이미 시작한 파일 쓰기의 최종 결과를 회수한 후 세션을 반환합니다. 따라서 느린 파일 시스템에서는 도구 시간 제한 직후에도 정리 시간이 필요할 수 있습니다. 보존할 수 없는 원문·상태는 조용히 버리지 않고 중단 사유를 표시합니다.

## 테스트와 실제 모델 평가

```sh
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

모의 LLM, 로컬 SSE 서버, 임시 소스 fixture로 실행 흐름, 충돌·용량·참조, 컨텍스트 제외 반복, 실패 시 보존, 스트림 인자 조립·끊김, 원문 재조회와 소스 변경을 검증합니다. 외부 API 키 없이 실행됩니다.

```sh
cargo run -- evaluate --suite eval/suite.toml --output eval/results/run-001
```

평가는 실제 API 요청을 사용합니다. 작은 Rust fixture와 이 저장소에 대해 완전 구현 / 기억 재사용 제한 조건을 각각 최소 3회 실행합니다. 두 조건 모두 같은 모델·작업 예산을 사용합니다. 제한 조건은 기억 본문 검색·로드와 자동 기억 목록을 끄되 목표·대화·원문 재조회는 유지합니다. 이것은 모든 형태의 기억이 없는 기준이 아닙니다.

소스 지문, 생성 문서, 시간, 토큰, 체크포인트·기억 조회 횟수, 조사·검증 수와 주제 키워드 포함 여부를 기록합니다. 소스가 바뀌면 중단합니다. 키워드 포함률은 예비 검사이며 사실 오류·근거 정확성은 별도 검토자가 채워야 합니다. 비용은 공급자 가격에 따라 토큰 집계에서 계산하세요.

OpenCode 비교는 동일 소스 지문, 같은 모델·요청, 비슷한 시간·총 토큰 예산으로 별도 3회 실행하고 같은 평가표로 채점합니다. 이 저장소는 OpenCode를 설치·실행하지 않습니다. 실제 모델 평가와 OpenCode 대비 품질 우위는 아직 확인되지 않았습니다.
