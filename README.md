# MnemoArc

세션 안에서 기억을 저장·검색·재사용하며 소스 코드를 조사하고 근거 있는 Markdown 문서를 만드는 에이전트입니다. **React 브라우저 UI를 내장한 Rust 실행 파일**로 배포합니다. 사용자의 컴퓨터에는 Node.js·npm이나 별도 UI 폴더가 필요하지 않습니다.

## 단일 실행 파일로 사용하기

해당 OS·CPU용 `mnemoarc`(Windows는 `mnemoarc.exe`)를 실행하면 로컬 서버가 시작되고 기본 브라우저가 자동으로 열립니다. 기본 포트는 3030이며, 이미 사용 중이면 빈 포트로 전환합니다. 실제 주소는 콘솔에도 표시합니다. 브라우저 자동 실행이 실패해도 표시된 주소로 직접 접속할 수 있습니다.

```sh
./mnemoarc
# 브라우저를 자동으로 열지 않으려면
./mnemoarc web --no-open
# 포트를 명시하면 충돌 시 다른 포트로 바꾸지 않고 오류를 표시합니다.
./mnemoarc web --port 3031
```

UI의 **앱 종료** 또는 터미널의 Ctrl+C로 진행 중인 작업을 정리하고 서버를 종료합니다. 브라우저 탭만 닫으면 작업과 서버는 계속 실행됩니다. 종료하면 RAM의 세션·기억은 사라지며 이미 저장한 문서는 유지됩니다.

설정은 `--config 경로` → `MNEMOARC_CONFIG_DIR/config.toml` → 현재 폴더의 기존 `config.toml` → 다음 사용자 경로 순으로 선택합니다. 기존 설정은 자동 이동하지 않습니다.

- macOS: `~/Library/Application Support/MnemoArc/config.toml`
- Windows: `%APPDATA%\MnemoArc\config.toml`
- Linux: `$XDG_CONFIG_HOME/mnemoarc/config.toml` 또는 `~/.config/mnemoarc/config.toml`

설정을 저장할 때 폴더와 파일을 생성합니다. 저장한 API 키는 설정 파일과 같은 위치의 `config.credentials.json`에 보관합니다. 조사할 프로젝트는 UI에서 선택하며, 결과 문서는 해당 프로젝트의 지정 경로에 저장합니다. `run` 등 headless 명령은 기존처럼 현재 폴더의 `config.toml` 또는 명시한 `--config`를 사용합니다.

### 배포 파일 빌드

빌드하는 컴퓨터에만 Node.js 22.12 이상과 Rust 2024 edition 도구 체인이 필요합니다.

```sh
npm ci
npm run build
```

배포할 파일은 `target/release/mnemoarc` 또는 `target/release/mnemoarc.exe` 하나입니다. React 빌드의 HTML·JS·CSS·폰트·Mermaid 청크를 모두 내장하며 실행 시 디스크에 풀지 않고 제공합니다. UI를 변경하면 `npm run build`를 다시 실행하세요. `frontend/dist/index.html`이 없으면 release 빌드는 실패하여 UI 없는 배포 파일 생성을 방지합니다. OS·CPU별 빌드와 대상 OS의 기본 시스템 라이브러리는 필요합니다.

## 소스에서 개발하기

Node.js와 Rust 도구 체인이 필요합니다. 다음 시작·종료 스크립트는 **개발용** Rust API와 Vite 서버를 실행합니다.

macOS / Linux:

```sh
./start_all.sh
./stop_all.sh
```

Windows (명령 프롬프트):

```bat
start_all.bat
stop_all.bat
```

시작 스크립트는 의존성이 없으면 `npm ci`로 설치하고 Rust를 빌드한 뒤 API와 React 개발 서버를 **백그라운드**에서 실행합니다. 준비가 완료되면 **http://127.0.0.1:5173**을 표시합니다. 터미널을 닫아도 서버가 유지되며, 종료 스크립트가 해당 프로젝트의 시작 스크립트로 실행한 서버만 종료합니다. 진행 중인 작업을 정리한 뒤 종료하므로 잠시 기다릴 수 있습니다. 종료하면 RAM의 세션·기억은 사라집니다.

중복 실행은 기존 주소를 표시합니다. 사용 중인 포트의 다른 프로세스는 종료하지 않습니다. 설치·빌드·서버 시작 로그는 Git에서 제외한 `.mnemoarc/services-YYYY-MM-DD.log`에 실행 중에도 날짜별로 저장합니다. 자정이 지나면 새 파일로 전환하고 오늘을 포함한 최근 3일치만 유지합니다. 서버가 출력하지 않아도 자정에 오래된 파일을 정리하며, 서버가 꺼져 있었다면 다음 시작 시 정리합니다. 보관 일수는 `MNEMOARC_LOG_RETENTION_DAYS` 환경변수(1~3650, 기본 3)로 설정할 수 있습니다. 기존 `services.log`도 최근 3일이 지나면 제거합니다. 대화·기억은 기록하지 않습니다. 이미 `npm run dev`로 실행했다면 해당 터미널에서 Ctrl+C로 종료한 뒤 시작하세요. 의존성 변경 후에는 `npm ci`를 다시 실행하세요.

포트를 변경하려면 시작 전에 환경변수를 지정합니다. 종료할 때는 포트를 다시 지정할 필요가 없습니다.

```sh
MNEMOARC_PORT=3031 MNEMOARC_FRONTEND_PORT=5174 ./start_all.sh
```

```bat
set MNEMOARC_PORT=3031
set MNEMOARC_FRONTEND_PORT=5174
start_all.bat
```

개발 로그를 터미널에서 직접 보려면 다음 명령도 사용할 수 있습니다.

```sh
npm install
npm run dev
```

브라우저에서 **http://127.0.0.1:5173**을 엽니다. 이 명령이 Rust API와 Vite 개발 서버를 함께 실행합니다. Ctrl+C로 두 서버를 종료합니다.

1. 왼쪽 **모든 설정**에서 서버 주소, 모델 이름, 모델 최대 컨텍스트, API 키를 입력합니다. OpenRouter를 사용할 때 모델 이름은 `qwen/qwen3.8-27b`입니다.
2. **연결 확인**으로 일반 응답·스트리밍·도구 호출을 확인하고 **설정 저장**을 누릅니다.
3. **프로젝트 관리**에서 폴더 선택 버튼으로 조사할 경로를 고르고 결과 문서 경로·독자·목적을 정합니다.
4. **이 프로젝트로 새 세션**을 눌러 채팅을 시작합니다.

설정 파일을 직접 작성하거나 `/set` 같은 명령을 입력할 필요가 없습니다. 인증 없이 동작하는 로컬 OpenAI 호환 서버도 사용할 수 있습니다. 모델 한도는 공급자가 제공하는 입력+출력 한도를 입력하세요. 실제 연결 확인은 모델 API 요청을 사용합니다.

빌드한 UI를 실행하려면 다음을 사용합니다.

```sh
npm run build
npm start
```

이때 내장 UI를 제공하는 서버를 실행하고 브라우저를 자동으로 엽니다. 로컬 컴퓨터에서만 접속할 수 있습니다. 개발 시 외부 UI 폴더를 제공하려면 `cargo run -- web --frontend frontend/dist --no-open`을 사용합니다. Vite 개발 서버 포트 설정은 `MNEMOARC_PORT=3031 npm run dev`를 사용할 수 있습니다. UI 빌드가 없는 debug 실행은 API를 제공하며 루트 화면에 빌드 안내를 표시합니다.

**전체 기본 설정**은 TOML로 저장하며, 현재 세션에도 적용할지 선택할 수 있습니다. **현재 세션만**을 선택하면 임시 설정으로 적용합니다. 진행 중인 요청은 시작 당시 설정을 사용하며 다음 요청부터 변경합니다. 한도를 줄였을 때 기존 상태가 들어가지 않으면 정리 후 적용하도록 보류합니다.

브라우저를 새로 고쳐도 Rust 서버가 실행 중이면 대화·기억·실행 상태를 다시 가져옵니다. 세션을 전환해도 실행을 취소하지 않으며 한 번에 하나의 작업만 실행합니다. 세션 종료 시 진행 중인 쓰기의 결과를 회수한 뒤 RAM 상태를 폐기합니다.

채팅 렌더링은 요청한 `llm_agent/frontend` 코드를 재사용했습니다. 추출 범위와 변경 사항은 [frontend/REUSE.md](frontend/REUSE.md)에 기록했습니다.

## 인증과 설정 파일

UI에서 API 키를 입력할 수 있습니다. 기본은 앱 실행 중에만 보관합니다. **이 기기에 키 저장**을 선택하면 `config.credentials.json`에 별도로 저장합니다. Unix 파일 권한은 `0600`이며 Git에서 제외합니다. 저장된 키는 API 응답이나 설정 화면에 다시 표시하지 않습니다. 브라우저 로컬 저장소에는 키·대화·기억을 저장하지 않습니다.

기존 환경변수 인증도 지원합니다. `api_key_env`로 지정한 환경변수 또는 `.env`의 키를 사용하며, UI에서 입력한 키가 우선합니다. 키 삭제는 앱에서 입력·저장한 키를 지웁니다. 프로세스의 환경변수 키를 바꾸려면 실행 환경에서 변경하세요.

일반 설정의 우선순위는 기본값 → `.env`/프로세스의 `MNEMOARC_*` → 저장된 TOML → 세션 임시 설정입니다. `config.example.toml`과 `.env.example`도 제공합니다. 별도 설정 파일은 `cargo run -- --config profile.toml web`으로 선택합니다.

UI 없이 같은 실행부를 사용할 수도 있습니다. 이때 인증은 환경변수 또는 `.env`로 제공합니다.

```sh
cargo run -- run --project /path/to/project --output docs/source-summary.md \
  --prompt '프로젝트 구조와 주요 흐름을 근거와 함께 문서화하고 검증해줘'
```

부분 완료·복구 가능한 중단은 종료 코드 2로 표시합니다. 취소하거나 프로그램을 종료해도 이미 작성한 결과 파일은 남습니다.

기존 문서의 요약·설명·Mermaid 요청은 관련 구간을 읽고 채팅으로 답하도록 안내합니다. 새 세션은 `file_list`, `file_read`, `document_inspect`, `source_search`, `code_outline`, `symbol_read`를 바로 제공하며, 프로젝트의 출력 경로를 자동으로 작성해야 할 산출물로 지정하지 않습니다. 소스 조사·문서 수정·검증은 해당 작업을 요청했을 때 수행하도록 지시합니다. 여러 읽기 결과는 남은 결과 예산을 균등하게 나누고, 잘린 본문은 파일/섹션 커서로 이어 읽습니다.

## 기억과 컨텍스트

- **상시 상태:** 목표·제약·진행, 참조 기억, 최신 20개와 관련 최대 5개의 메타데이터를 매 요청에 제공합니다. 과거 상태 묶음을 누적하지 않습니다.
- **개별 기억:** 키/ID, 본문, 태그, 개정 번호, 종류·상태와 프로그램이 발급한 출처를 RAM에 저장합니다. 조회는 최신순을 바꾸지 않습니다. 선형 키워드 검색은 한국어 부분 문자열과 코드 식별자를 지원합니다.
- **원문:** 완료된 메시지·도구 묶음을 RAM에 보관하고 필요할 때 다시 검색·조회합니다. 컨텍스트 제외와 원문 폐기는 별개입니다.

기억은 같은 키를 갱신할 때 기존 개정 번호가 필요합니다. 참조 중인 기억은 해제하거나 원자적으로 교체해야 삭제할 수 있습니다. 목록 커서는 변경 시 만료됩니다. 용량 초과는 삭제 후보와 오류로 알리며 임의로 기억을 버리지 않습니다.

입력 예산의 80%에서 체크포인트를 준비하고 60% 이하를 목표로 합니다. 기억 저장 또는 저장 불필요 사유와 진행 요약을 확인한 뒤 지정된 완결 묶음만 제외합니다. `checkpoint_complete`의 필수 `progress`와 선택적 `next`로 진행 상태도 함께 저장합니다. 저장 실패·잘못된 인자·취소 시에는 제외하지 않습니다. 정리 요청 3회분의 여유를 사전에 확보하고, 정리 중에는 기억·진행·원문 도구와 기존 근거의 정확한 ID를 찾는 `source_lookup`을 제공합니다. 이 조회는 새 파일을 읽거나 근거를 만들어내지 않습니다. 추론 모델의 출력을 자르지 않도록 정리 요청에도 설정된 출력 한도를 사용하며, 정리 도구 결과는 `checkpoint_tokens`와 1,024 토큰 중 작은 값 이내로 제한합니다. 완료가 확인되면 해당 정리 대화도 활성 컨텍스트에서 제외하되 원문에는 보관합니다. 성공한 저장과 실패 재시도를 구분해 실패 요청 8회 또는 전체 정리 요청 8회에 도달하면 마지막 실패 원인과 함께 세션을 보존한 채 중단합니다. 4~8번째 요청은 실제 입력·출력 공간과 실행 예산이 남아 있을 때만 허용합니다. 원문 폐기는 검토되고 이미 제외된 구간에만 적용합니다.

알려진 모델은 `tiktoken-rs` 토크나이저를 사용합니다. 알 수 없는 모델 이름은 `cl100k_base` 기준 토큰 수에 25% 여유를 더해 추정하며, UI에서 실제 API 사용량과 컨텍스트 추정 여부를 구분합니다. 공급자 토크나이저와 정확히 일치하는 값은 아닙니다. 기억 메타데이터에는 항목별 160 토큰 거부 한도가 없으며, 기억 인덱스 컨텍스트는 `index_tokens` 예산에 맞는 항목만 포함합니다. 예산을 넘은 항목은 저장된 상태로 남고 생략된 ID가 상태에 표시되며 `memory_find`·`memory_read`로 조회할 수 있습니다. 긴 설명은 본문에 저장하세요. 서버가 제공하지 않은 사용량·캐시 사용량은 0으로 취급하지 않습니다.

## 파일 조사와 검증

`source-docs`를 선택하면 파일 목록, 경로·정규식 검색, 줄 범위 읽기, 문서 작성·삽입·교체·삭제, 조사 목록 도구가 활성화됩니다. 문서는 조사한 섹션부터 나눠 저장하며, 새 섹션을 중간에 넣을 때는 목차의 기존 제목을 기준으로 삽입할 수 있습니다. 선택 변경은 현재 호출 묶음 뒤에 적용합니다. 읽기만 최대 4개 병렬이며 상태 변경·쓰기는 순서대로 실행합니다.

읽기는 프로젝트 루트와 포함·제외 규칙을 따릅니다. VCS 내부, 빌드 산출물, 의존성 디렉터리, 바이너리·비 UTF-8·16MiB 초과 파일은 기본 조사 대상에서 제외합니다. 심볼릭 링크를 따라 프로젝트 밖으로 나갈 수 없습니다. 검색 결과는 페이지 커서로 이어 읽으며 변경 시 커서가 만료됩니다.

쓰기는 지정한 **한 결과 문서 경로**에만 허용합니다. 기존 파일의 해시와 부분 편집 대상의 유일성을 확인하고 임시 파일을 동기화한 뒤 교체합니다. 문서 섹션은 목차의 적절한 위치에 삽입할 수 있고, 문장·문단은 고유한 원문을 기준으로 앞뒤 삽입·교체·삭제할 수 있습니다. 호출 ID별 성공 결과를 보존하여 같은 호출을 재실행하지 않습니다. 일반 소스 수정과 셸 실행 도구는 제공하지 않습니다.

단순 문서 편집·요약 추가는 저장한 내용의 해시를 확인한 뒤 완료하며, 조사 항목이 없다는 이유만으로 재시도하지 않습니다. 소스 근거 검증이 필요한 문서 작업은 먼저 `task_state`의 `require_investigation=true`로 선언합니다. 이 요구는 같은 요청 안에서 해제할 수 없고, 새 사용자 요청에서 초기화되며 작업 재개에서는 유지됩니다. 이미 등록된 조사 항목의 검증·문서 감사는 계속 적용됩니다.

조사 항목은 미조사 → 조사 중 → 작성됨 → 검증됨으로 진행합니다. 기억 개정, 소스 해시·줄·관찰 시각, 문서 섹션 해시를 연결합니다. 소스나 해당 섹션이 바뀌면 재검증이 필요합니다. `검증됨`은 에이전트가 원문 대조 기록을 남겼고 해시가 유효하다는 뜻이며 사실 정확성 자체를 자동 증명하는 점수는 아닙니다.

| `tools` | 정적 레지스트리, 입력·권한 검사, 파일·문서·기억 도구 |

기억·대화·출처·호출 결과는 디스크 로그나 DB에 쓰지 않습니다. 세션 종료·프로그램 종료 시 사라집니다. 프로젝트 설정과 결과 문서, 사용자가 저장을 선택한 인증 설정은 남습니다. 평가 명령은 명시적으로 요청한 평가 결과 문서와 집계 JSON도 저장합니다.

용량은 직렬화된 논리 데이터 크기로 계산하며 프로세스 전체 RSS 한도는 아닙니다. 취소 시 이미 시작한 파일 쓰기의 최종 결과를 회수한 후 세션을 반환합니다. 따라서 느린 파일 시스템에서는 도구 시간 제한 직후에도 정리 시간이 필요할 수 있습니다. 보존할 수 없는 원문·상태는 조용히 버리지 않고 중단 사유를 표시합니다.

## 테스트와 실제 모델 평가

```sh
npm test
npm run test:scripts # 시작·종료 스크립트만 검증
npm run test:ui # Chrome이 설치되어 있어야 합니다. 실제 Rust API + 모의 SSE 서버 사용
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

브라우저 테스트는 모든 설정의 UI 노출, 설정·키 저장, 채팅 렌더링·스트리밍, 세션 전환·취소·새로고침, 폴더 선택과 좁은 화면을 검증합니다. 모의 LLM, 로컬 SSE 서버, 임시 소스 fixture로 실행 흐름, 충돌·용량·참조, 컨텍스트 제외 반복, 실패 시 보존, 스트림 인자 조립·끊김, 원문 재조회와 소스 변경을 검증합니다. 외부 API 키 없이 실행됩니다.

```sh
cargo run -- evaluate --suite eval/suite.toml --output eval/results/run-001
```

평가는 실제 API 요청을 사용합니다. 작은 Rust fixture와 이 저장소에 대해 완전 구현 / 기억 재사용 제한 조건을 각각 최소 3회 실행합니다. 두 조건 모두 같은 모델·작업 예산을 사용합니다. 제한 조건은 기억 본문 검색·로드와 자동 기억 목록을 끄되 목표·대화·원문 재조회는 유지합니다. 이것은 모든 형태의 기억이 없는 기준이 아닙니다.

소스 지문, 생성 문서, 시간, 토큰, 체크포인트·기억 조회 횟수, 조사·검증 수와 주제 키워드 포함 여부를 기록합니다. 소스가 바뀌면 중단합니다. 키워드 포함률은 예비 검사이며 사실 오류·근거 정확성은 별도 검토자가 채워야 합니다. 비용은 공급자 가격에 따라 토큰 집계에서 계산하세요.

OpenCode 비교는 동일 소스 지문, 같은 모델·요청, 비슷한 시간·총 토큰 예산으로 별도 3회 실행하고 같은 평가표로 채점합니다. 이 저장소는 OpenCode를 설치·실행하지 않습니다. 실제 모델 평가와 OpenCode 대비 품질 우위는 아직 확인되지 않았습니다.

### 문서 조사·검증 도구

`source-docs`에 문서 목차·섹션 조회(`document_inspect`), 섹션 단위 수정,
출처 일괄 점검(`document_audit`), 조사 항목 일괄 검증(`verify_batch`),
선언 검색(`symbol_search`)이 포함된다. 파일 읽기는 실제 줄 수와 줄 위치를 제공한다.
설정 화면의 **실행과 예산**에서 작성·검증 예산 비율과 반복 조회·중단 제한을 조절할 수 있다.
상세 사용법과 검증 범위는 [문서 도구 개선](docs/documentation-tools.md)을 참고한다.

### 도구 오류 복구와 진행 표시

- 출처는 프로세스 내 병렬 작업에서도 충돌하지 않는 짧은 `S123` 형태의 ID를 사용합니다. 알 수 없는 ID는 최근 출처의 ID·경로·행 범위와 함께 재조회 방법을 안내하며, 임의의 출처로 자동 치환하지 않습니다.
- 출처 없는 사실 기억과 추론 기억은 `needs_review`로 표시합니다. 기존 사실 기억을 갱신하면서 근거를 조용히 제거할 수 없습니다.
- 검색의 `path_glob`은 파일 경로 필터, `query`는 내용 또는 심볼 이름입니다. 기존 `pattern`은 호환 별칭입니다. 심볼 결과의 `matched_files`와 `scanned_files`로 파일 미발견과 선언 미발견을 구분합니다.
- 재개는 진행 단계를 유지합니다. `task_state`의 `phase`로 `investigate`, `draft`, `verify`, `answer`를 기록할 수 있습니다. 문서 작성·검증 항목이 없는 대화 작업은 6회 모델 호출 후 답변을 우선하도록 안내하되, 필요한 추가 근거 읽기는 허용합니다. 새 요청은 단계와 호출 수를 초기화하며, “계속 진행” 또는 resume은 유지합니다.
- 실행 중 화면에는 모델 응답 대기, 도구 실행, 답변 생성과 현재 단계의 경과 시간·호출 횟수를 표시합니다. 모델 대기 시간은 공급자 대기·추론·전송 시간을 별도로 구분한 값은 아닙니다.

### 출력 길이 제한 시 이어받기

공급자가 `finish_reason=length`와 정상 스트림 종료를 반환하면 받은 답변과 사용량을 보존하고 자동으로 이어서 요청합니다. 화면에서는 조각을 하나의 Markdown 답변으로 합칩니다. 잘린 도구 호출 묶음은 실행하지 않으며, 필요한 호출을 완전한 인자로 다시 생성하도록 요청합니다. 전체 예산·시간·취소 제한은 그대로 적용되고 한 실행에서 길이 초과가 8번 연속 발생하면 부분 답변을 남기고 중단합니다. 추론만 생성되어 표시할 텍스트가 없다면 복원할 답변이 없으므로 짧은 답변을 새로 요청합니다. 네트워크 단절은 이 길이 제한 복구와 구분합니다.

### 파일 이어읽기 커서

`file_read`의 새 읽기는 `path`, `start_line`, `max_lines`를 사용합니다. 결과가 잘리면 `next_cursor`의 `cursor`만 넘깁니다(예: `{"cursor":"R123"}`). 서버가 원래 경로·범위·문자 위치·파일 해시를 보관하므로 모델이 위치를 계산할 필요가 없습니다. 커서와 경로·행 번호·offset을 함께 전달하면 거부하며 파일이 바뀌거나 다른 세션의 커서이면 새 읽기를 안내합니다. 커서는 요청했던 범위가 끝나면 종료됩니다. 더 뒤의 범위가 필요하면 `next_line`으로 새 읽기를 시작합니다. 기존 클라이언트의 offset 입력은 호환용으로 유지하지만 모델 도구 스키마에는 제공하지 않습니다.

### 섹션 제목과 결과 파일 경로

섹션 인자의 `#`는 생략할 수 있습니다. 예를 들어 `1. 시스템 개요`가 문서에서 유일하면 `## 1. 시스템 개요`로 해석합니다. 중첩된 문서의 목차에는 `level`과 상위 제목을 포함한 `section_path`가 나오므로, 다른 부모 아래 같은 제목이 있을 때 이 경로를 `section`에 복사할 수 있습니다. 같은 경로까지 중복되면 `ambiguous_section`, 제목이 없으면 `section_not_found`를 반환합니다. 섹션 전체 편집은 자손도 교체하므로 작은 수정에는 `section`으로 범위를 좁힌 텍스트 편집을 사용합니다. 새 자식은 `insert_first_child` 또는 `insert_last_child`, 동급 섹션 사이는 `insert_before` 또는 `insert_after`로 추가할 수 있습니다.

파일 읽기의 상대 경로는 프로젝트 루트 기준입니다. 프로젝트 밖 결과 파일을 읽을 때에는 `document_inspect`가 반환한 절대 경로를 그대로 사용합니다. 이 규칙과 예시는 모델 도구 설명·path 인자 설명에 포함되며, 도구 설정 화면에도 현재 프로젝트 루트와 결과 경로를 표시합니다.

도구 인자 오류를 줄이기 위해 `file_read`는 `limit`을 `max_lines`의 별칭으로 허용합니다. 서로 다른 두 값이나 `limit`과 0이 아닌 `offset`의 혼용은 거부하고 새 범위·커서 사용법을 안내합니다. `investigation`은 action별 인자를 검사합니다. `upsert`는 신규 등록 시 최상위 `title`이 필수이며 기존 ID 수정 시 생략한 제목을 유지하고, `items`는 기존 항목의 `verify_batch` 전용입니다. 잘못된 조합은 상태 변경 전에 해당 action의 호출 예시와 함께 거부합니다.

### 입력 문서와 읽기 범위 확인

`document_inspect`에 `path`를 주면 프로젝트 내 입력 문서의 목차·섹션을 조회하며, 생략하면 설정된 결과 문서를 조회합니다. 섹션 이어 읽기는 경로와 파일 해시를 유지합니다.

섹션 없이 조회하면 현재 파일 버전에 대해 실제 전달된 줄 수, 아직 완전히 읽지 않은 줄 범위, 목차별 `fully_read`를 확인할 수 있습니다. 읽기 범위는 최종 토큰 제한 후 전달한 본문을 기준으로 세션에 보관하며 파일 변경 시 이전 기록을 적용하지 않습니다. 이는 내용 이해나 사실 검증을 뜻하지 않습니다. 인자와 응답 필드는 [문서 도구 설명](docs/documentation-tools.md#입력-문서-조회와-읽기-범위)을 참고하세요.

### 백엔드 오류와 종료 처리

모델·도구 작업에서 패닉이 발생하면 오류로 표시하고 세션을 보존합니다. 도구 패닉 이후 같은 호출 묶음의 후속 도구는 실행하지 않습니다. 완료된 파일 쓰기는 되돌리지 않으며 결과 확인이 필요하다는 오류를 남깁니다. 웹 실행 경계에서도 예기치 않은 패닉 이후 실행 상태를 해제해 새 요청과 종료가 계속 막히지 않도록 합니다.

취소는 가득 찬 이벤트 채널 대기에서도 처리합니다. 모델 응답이 끝나면 스트리밍 수신 채널을 닫고 이미 받은 내용을 처리하므로, 송신 핸들이 남아 있어도 채널 종료를 무한정 기다리지 않습니다. 종료가 시작되면 실행 잠금을 획득한 뒤에도 새 실행을 거부합니다. 숫자 입력에 대한 페이지·예산 계산은 오버플로를 방지하고, 지원 범위를 넘는 타임아웃은 설정 단계에서 거부합니다.

진행 중인 파일 쓰기는 취소나 제한 시간 이후에도 최종 결과를 회수합니다. 운영체제 수준에서 파일 I/O가 멈춘 경우까지 강제 종료하거나, 메모리 부족·프로세스 강제 종료에서 복구하는 보장은 아닙니다.

이벤트 전송은 사용자 취소뿐 아니라 현재 실행의 마감 시간도 따릅니다. 마감 후에는 상태 알림을 비차단 방식으로만 시도하며, 세션 결과는 실행 반환값으로 보존합니다. 상태 전송을 기다리는 동안 마감이 지났다면 새 모델 요청이나 파일 쓰기를 시작하지 않습니다. 상위 실행이 중단되거나 패닉으로 해제될 때 스트리밍 중계 작업도 중단해 채널 핸들이 남지 않도록 합니다.

OpenAI 호환 클라이언트를 직접 호출할 때도 설정과 요청 JSON의 객체 형태를 먼저 검증합니다. 취소는 HTTP 응답 본문 읽기와 가득 찬 델타 채널 전송을 포함해 요청 시도 전체에 적용합니다. 연결 확인 API도 앱 종료 신호를 받으면 진행 중인 확인 요청을 중단하고 503을 반환합니다.

결과 문서 미리보기와 소스 읽기는 일반 파일만 허용합니다. Unix에서는 비차단 열기와 파일 핸들의 유형 재검사로 FIFO 대기 및 파일 유형 교체를 방어합니다. 소스 읽기의 16MiB 제한은 실제 읽기에도 적용하며, 미리보기는 UTF-8 문자 중간에서 잘리지 않도록 반환 범위를 조정합니다.


### 코드 탐색 개선

파일명 탐색에는 `file_list mode=paths`를 사용해 본문 읽기를 생략할 수 있습니다. 기존 텍스트 전용 목록은 기본 `mode=text`로 유지됩니다. `source_search`는 대소문자·단어 경계 옵션, 앞뒤 문맥, 일치 파일 목록과 파일별 일치 줄 수를 지원합니다. 내용·심볼 검색의 중복 파일 읽기를 제거하고, 내용 검색은 반환할 페이지의 결과만 보관합니다. 파일 변경 감지를 위해 다음 페이지에서도 내용을 재검사합니다. 사용 예와 출처 범위는 [코드 탐색 옵션](docs/documentation-tools.md#코드-탐색-옵션)을 참고하세요.


새 세션의 탐색 도구 기본 제공, 구문 트리 캐시와 호출·입력 토큰 회귀 기준은 [탐색 효율 개선 기록](docs/navigation-efficiency-improvement.md)을 참고하세요. 실제 모델 평가의 남은 실패도 기록했습니다.

소스 채팅 답변은 기본적으로 이미 읽은 근거로 동일 모델이 한 번 검토한 뒤 표시합니다. `source_answer_review` 설정으로 끌 수 있으며 추가 호출 비용이 발생합니다. 명시적 JSON 인용의 읽기 범위·파일 변경 검사와 적용 범위는 [소스 답변 검토 설계](docs/source-answer-review.md)를 참고하세요. 여러 문자열 검색은 `source_search queries:["abort", "signal"]`처럼 정규식 없이 수행할 수 있습니다.

### Tree-sitter 구조 탐색

`source-docs` 그룹의 `code_outline`, `symbol_read`로 코드 구조와 심볼 본문을 탐색합니다. 구현과 자동 테스트는 Rust로 작성했습니다. Tree-sitter는 네이티브 파서의 Rust 바인딩을 사용하며 Rust, JavaScript/JSX, TypeScript/TSX, Python, Java, C#을 분석합니다.

구조 조회는 별도 서버 설치 없이 사용할 수 있습니다. 같은 내용·언어의 구문 트리는 최대 8개, 원문 크기 합계 4MiB까지 캐시해 반복 파싱을 줄입니다(트리 자체의 메모리 크기 한도를 뜻하지 않습니다). 매 호출에서 파일 권한·현재 내용 해시를 다시 확인하며 출처와 필터 결과는 재사용하지 않습니다. 사용 예와 검증 범위는 [구조 탐색](docs/documentation-tools.md#구조-탐색)을 참고하세요.

LLM은 `code_outline`의 `view=compact`, `max_depth=0`으로 최상위 구조를 확인하고, `query`·`match=exact`·공통 `kind`·정확한 `container`로 범위를 좁힌 뒤 `symbol_read`로 본문을 읽을 수 있습니다. 기본 상세 응답은 유지하며 간결한 목록은 출처 근거로 취급하지 않습니다. 다음 페이지 호출에는 모든 필터가 전달되고 조건 변경 시 커서를 거부합니다.

함수 목록에는 `kind=function`을 사용하고, 인자·기본값·선언된 반환 타입은 상세 시그니처와 `signature_source`로 먼저 확인합니다. `signature_truncated`가 잘림 여부를 알립니다. 본문이 필요하면 `symbol_read`의 `max_lines`와 파일 절대 줄 번호인 `start_line`으로 심볼 안의 필요한 부분만 읽을 수 있습니다.

LLM에는 읽은 본문을 절대 줄 번호와 함께 전달하고, 구조 목록에는 복사 가능한 `location`을 제공합니다. 원문과 커서 오프셋은 유지하며 모델용 줄 번호도 응답 토큰 예산에 반영합니다.

소스 문서는 `task_state.patch.workflow="source_document"`로 시작해 조사·작성 도구를 즉시 활성화합니다. `source_document_review`는 생성 문서와 실제 소스·요구사항을 제한된 별도 요청으로 대조하며 기본값은 `true`입니다. 비용 상한과 재현 방법은 [소스 문서 작업·검토 설계](docs/source-document-review.md)를 참고하세요.

### 프록시 강제 비활성화

설정 화면의 **프록시 강제 비활성화**를 켜거나 설정 파일에 `disable_proxy = true`를 지정하면 모든 LLM HTTP 요청(내용 검토·재시도 포함)에서 직접 연결합니다. `proxy` 주소와 환경변수·시스템 프록시 자동 감지를 모두 무시합니다. 기존 프록시 주소는 보존되며, 옵션을 다시 끄면 기존 동작으로 돌아갑니다. 기본값은 `false`입니다. `proxy`만 비우는 것은 강제 비활성화가 아닙니다.

### Qwen thinking/reasoning 비활성화

설정 화면의 **LLM 추론 사용**을 끄거나 설정 파일에 `enable_thinking = false`를 지정하면 LLM 호출은 유지하면서 Qwen의 thinking/reasoning만 완전히 끕니다. 요청에는 `reasoning_effort = "none"`을 보내며, 저장해 둔 `reasoning_effort` 값보다 이 토글이 우선합니다. 다시 켜면 저장된 추론 강도를 사용합니다.
