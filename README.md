# MnemoArc

세션 안에서 기억을 저장·검색·재사용하며 소스 코드를 조사하고 근거 있는 Markdown 문서를 만드는 에이전트입니다. **Node.js + React 브라우저 UI**와 Rust 실행부로 구성됩니다. 기존 터미널 UI는 브라우저 화면으로 교체했습니다.

## 시작하기

Node.js 22.12 이상과 Rust 2024 edition 도구 체인이 필요합니다. 프로젝트 루트의 시작·종료 스크립트를 사용하세요.

macOS / Linux:

```sh
./start_all.sh
./stop_all.sh
```

Windows (명령 프롬프트):

```bat
start_all.bat
stop_all.bat
```

시작 스크립트는 의존성이 없으면 `npm ci`로 설치하고 Rust를 빌드한 뒤 API와 React 개발 서버를 **백그라운드**에서 실행합니다. 준비가 완료되면 **http://127.0.0.1:5173**을 표시합니다. 터미널을 닫아도 서버가 유지되며, 종료 스크립트가 해당 프로젝트의 시작 스크립트로 실행한 서버만 종료합니다. 진행 중인 작업을 정리한 뒤 종료하므로 잠시 기다릴 수 있습니다. 종료하면 RAM의 세션·기억은 사라집니다.

중복 실행은 기존 주소를 표시합니다. 사용 중인 포트의 다른 프로세스는 종료하지 않습니다. 설치·빌드·서버 시작 로그는 Git에서 제외한 `.mnemoarc/services.log`에 저장하며, 대화·기억은 기록하지 않습니다. 이미 `npm run dev`로 실행했다면 해당 터미널에서 Ctrl+C로 종료한 뒤 시작하세요. 의존성 변경 후에는 `npm ci`를 다시 실행하세요.

포트를 변경하려면 시작 전에 환경변수를 지정합니다. 종료할 때는 포트를 다시 지정할 필요가 없습니다.

```sh
MNEMOARC_PORT=3031 MNEMOARC_FRONTEND_PORT=5174 ./start_all.sh
```

```bat
set MNEMOARC_PORT=3031
set MNEMOARC_FRONTEND_PORT=5174
start_all.bat
```

개발 로그를 터미널에서 직접 보려면 다음 명령도 사용할 수 있습니다.

```sh
npm install
npm run dev
```

브라우저에서 **http://127.0.0.1:5173**을 엽니다. 이 명령이 Rust API와 Vite 개발 서버를 함께 실행합니다. Ctrl+C로 두 서버를 종료합니다.

1. 왼쪽 **모든 설정**에서 서버 주소, 모델 이름, 모델 최대 컨텍스트, API 키를 입력합니다.
2. **연결 확인**으로 일반 응답·스트리밍·도구 호출을 확인하고 **설정 저장**을 누릅니다.
3. **프로젝트 관리**에서 폴더 선택 버튼으로 조사할 경로를 고르고 결과 문서 경로·독자·목적을 정합니다.
4. **이 프로젝트로 새 세션**을 눌러 채팅을 시작합니다.

설정 파일을 직접 작성하거나 `/set` 같은 명령을 입력할 필요가 없습니다. 인증 없이 동작하는 로컬 OpenAI 호환 서버도 사용할 수 있습니다. 모델 한도는 공급자가 제공하는 입력+출력 한도를 입력하세요. 실제 연결 확인은 모델 API 요청을 사용합니다.

빌드한 UI를 실행하려면 다음을 사용합니다.

```sh
npm run build
npm start
```

이때 주소는 **http://127.0.0.1:3030**입니다. Rust 서버가 React 빌드 파일도 제공합니다. 기본적으로 로컬 컴퓨터에서만 접속할 수 있습니다. 다른 로컬 포트는 `cargo run -- web --port 3031`로 지정합니다. 개발 시에는 `MNEMOARC_PORT=3031 npm run dev`를 사용할 수 있습니다.

| 화면 | 기능 |
|---|---|
| 왼쪽 프로젝트·세션 | 프로젝트별 새 세션, 세션 전환, 현재 실행 위치 표시 |
| 채팅 | 스트리밍 Markdown, 코드·표·수식·Mermaid, 도구 결과, 이전 대화 조회 |
| 상단 세션 버튼 | 작업 재개, 기억 정리, 실행 중지, 세션 종료 |
| 기억 패널 | 제목·태그·키 검색, 기억 본문·출처, 사용량·체크포인트 |
| 진행 패널 | 목표·제약·완료 조건, 발견·미확인 사항, 조사 목록 |
| 도구 패널 | 선택 도구 켜기·끄기, 기본 도구 확인 |
| 문서 패널 | 생성된 Markdown 읽기·내려받기 |
| 프로젝트 패널 | 현재 세션의 문서 경로·목적·독자·파일 규칙 편집 |
| 프로젝트 관리 | 폴더 탐색, 프로젝트 등록·수정·제거, 기본값 저장 |
| 모든 설정 | 모델 연결, 인증·프록시·지원 옵션, 기억·원문·컨텍스트 예산, 시간·재시도·검토 제한 |

**전체 기본 설정**은 TOML로 저장하며, 현재 세션에도 적용할지 선택할 수 있습니다. **현재 세션만**을 선택하면 임시 설정으로 적용합니다. 진행 중인 요청은 시작 당시 설정을 사용하며 다음 요청부터 변경합니다. 한도를 줄였을 때 기존 상태가 들어가지 않으면 정리 후 적용하도록 보류합니다.

브라우저를 새로 고쳐도 Rust 서버가 실행 중이면 대화·기억·실행 상태를 다시 가져옵니다. 세션을 전환해도 실행을 취소하지 않으며 한 번에 하나의 작업만 실행합니다. 세션 종료 시 진행 중인 쓰기의 결과를 회수한 뒤 RAM 상태를 폐기합니다.

채팅 렌더링은 요청한 `llm_agent/frontend` 코드를 재사용했습니다. 추출 범위와 변경 사항은 [frontend/REUSE.md](frontend/REUSE.md)에 기록했습니다.

## 인증과 설정 파일

UI에서 API 키를 입력할 수 있습니다. 기본은 앱 실행 중에만 보관합니다. **이 기기에 키 저장**을 선택하면 `config.credentials.json`에 별도로 저장합니다. Unix 파일 권한은 `0600`이며 Git에서 제외합니다. 저장된 키는 API 응답이나 설정 화면에 다시 표시하지 않습니다. 브라우저 로컬 저장소에는 키·대화·기억을 저장하지 않습니다.

기존 환경변수 인증도 지원합니다. `api_key_env`로 지정한 환경변수 또는 `.env`의 키를 사용하며, UI에서 입력한 키가 우선합니다. 키 삭제는 앱에서 입력·저장한 키를 지웁니다. 프로세스의 환경변수 키를 바꾸려면 실행 환경에서 변경하세요.

일반 설정의 우선순위는 기본값 → `.env`/프로세스의 `MNEMOARC_*` → 저장된 TOML → 세션 임시 설정입니다. `config.example.toml`과 `.env.example`도 제공합니다. 별도 설정 파일은 `cargo run -- --config profile.toml web`으로 선택합니다.

UI 없이 같은 실행부를 사용할 수도 있습니다. 이때 인증은 환경변수 또는 `.env`로 제공합니다.

```sh
cargo run -- run --project /path/to/project --output docs/source-summary.md \
  --prompt '프로젝트 구조와 주요 흐름을 근거와 함께 문서화하고 검증해줘'
```

부분 완료·복구 가능한 중단은 종료 코드 2로 표시합니다. 취소하거나 프로그램을 종료해도 이미 작성한 결과 파일은 남습니다.

## 기억과 컨텍스트

- **상시 상태:** 목표·제약·진행, 참조 기억, 최신 20개와 관련 최대 5개의 메타데이터를 매 요청에 제공합니다. 과거 상태 묶음을 누적하지 않습니다.
- **개별 기억:** 키/ID, 본문, 태그, 개정 번호, 종류·상태와 프로그램이 발급한 출처를 RAM에 저장합니다. 조회는 최신순을 바꾸지 않습니다. 선형 키워드 검색은 한국어 부분 문자열과 코드 식별자를 지원합니다.
- **원문:** 완료된 메시지·도구 묶음을 RAM에 보관하고 필요할 때 다시 검색·조회합니다. 컨텍스트 제외와 원문 폐기는 별개입니다.

기억은 같은 키를 갱신할 때 기존 개정 번호가 필요합니다. 참조 중인 기억은 해제하거나 원자적으로 교체해야 삭제할 수 있습니다. 목록 커서는 변경 시 만료됩니다. 용량 초과는 삭제 후보와 오류로 알리며 임의로 기억을 버리지 않습니다.

입력 예산의 80%에서 체크포인트를 준비하고 60% 이하를 목표로 합니다. 기억 저장 또는 저장 불필요 사유와 진행 요약을 확인한 뒤 지정된 완결 묶음만 제외합니다. `checkpoint_complete`의 필수 `progress`와 선택적 `next`로 진행 상태도 함께 저장합니다. 저장 실패·잘못된 인자·취소 시에는 제외하지 않습니다. 정리 요청 3회분의 여유를 사전에 확보하고, 정리 중에는 기억·진행·원문 도구만 제공합니다. 추론 모델의 출력을 자르지 않도록 정리 요청에도 설정된 출력 한도를 사용하며, 정리 도구 결과는 `checkpoint_tokens`와 1,024 토큰 중 작은 값 이내로 제한합니다. 완료가 확인되면 해당 정리 대화도 활성 컨텍스트에서 제외하되 원문에는 보관합니다. 3회로 해결되지 않으면 세션을 보존한 채 중단합니다. 원문 폐기는 검토되고 이미 제외된 구간에만 적용합니다.

알려진 모델은 `tiktoken-rs` 토크나이저를 사용합니다. 알 수 없는 모델 이름은 `cl100k_base` 기준 토큰 수에 25% 여유를 더해 추정하며, UI에서 실제 API 사용량과 컨텍스트 추정 여부를 구분합니다. 공급자 토크나이저와 정확히 일치하는 값은 아닙니다. 기억 메타데이터는 항목당 160 토큰 이내여야 하며, 초과 오류에는 계산량을 표시합니다. 긴 설명은 본문에 저장하세요. 서버가 제공하지 않은 사용량·캐시 사용량은 0으로 취급하지 않습니다.

## 파일 조사와 검증

`source-docs`를 선택하면 파일 목록, 경로·정규식 검색, 줄 범위 읽기, 문서 작성·추가·정확 부분 교체, 조사 목록 도구가 활성화됩니다. 선택 변경은 현재 호출 묶음 뒤에 적용합니다. 읽기만 최대 4개 병렬이며 상태 변경·쓰기는 순서대로 실행합니다.

읽기는 프로젝트 루트와 포함·제외 규칙을 따릅니다. VCS 내부, 빌드 산출물, 의존성 디렉터리, 바이너리·비 UTF-8·16MiB 초과 파일은 기본 조사 대상에서 제외합니다. 심볼릭 링크를 따라 프로젝트 밖으로 나갈 수 없습니다. 검색 결과는 페이지 커서로 이어 읽으며 변경 시 커서가 만료됩니다.

쓰기는 지정한 **한 결과 문서 경로**에만 허용합니다. 기존 파일의 해시와 부분 교체 대상의 유일성을 확인하고 임시 파일을 동기화한 뒤 교체합니다. 호출 ID별 성공 결과를 보존하여 같은 호출을 재실행하지 않습니다. 일반 소스 수정과 셸 실행 도구는 제공하지 않습니다.

조사 항목은 미조사 → 조사 중 → 작성됨 → 검증됨으로 진행합니다. 기억 개정, 소스 해시·줄·관찰 시각, 문서 섹션 해시를 연결합니다. 소스나 해당 섹션이 바뀌면 재검증이 필요합니다. `검증됨`은 에이전트가 원문 대조 기록을 남겼고 해시가 유효하다는 뜻이며 사실 정확성 자체를 자동 증명하는 점수는 아닙니다.

## 구조와 보관 범위

| 모듈 | 책임 |
|---|---|
| `agent` | 단일 실행 소유자, 예산·취소, 도구 순서, 안전 경계 설정 적용 |
| `session` | 세션별 상태, 원문, 조사 목록, 호출 결과 기록 |
| `memory` | 개정 기반 CRUD, 검색, 원자적 교체, 용량 검사 |
| `context` | 요청 구성, 토큰 계산, 체크포인트 준비·확인·제외 |
| `tools` | 정적 레지스트리, 입력·권한 검사, 파일·문서·기억 도구 |
| `llm` | OpenAI 호환 SSE, 호출 인자 조립, 사용량·재시도 |
| `web` / `config` | 로컬 HTTP·SSE API, 설정 검증·인증·TOML |
| `frontend` | React + Vite UI, 재사용한 채팅 렌더링 |
| `evaluation` | 고정 소스 반복 실행과 집계 결과 |

기억·대화·출처·호출 결과는 디스크 로그나 DB에 쓰지 않습니다. 세션 종료·프로그램 종료 시 사라집니다. 프로젝트 설정과 결과 문서, 사용자가 저장을 선택한 인증 설정은 남습니다. 평가 명령은 명시적으로 요청한 평가 결과 문서와 집계 JSON도 저장합니다.

용량은 직렬화된 논리 데이터 크기로 계산하며 프로세스 전체 RSS 한도는 아닙니다. 취소 시 이미 시작한 파일 쓰기의 최종 결과를 회수한 후 세션을 반환합니다. 따라서 느린 파일 시스템에서는 도구 시간 제한 직후에도 정리 시간이 필요할 수 있습니다. 보존할 수 없는 원문·상태는 조용히 버리지 않고 중단 사유를 표시합니다.

## 테스트와 실제 모델 평가

```sh
npm test
npm run test:scripts # 시작·종료 스크립트만 검증
npm run test:ui # Chrome이 설치되어 있어야 합니다. 실제 Rust API + 모의 SSE 서버 사용
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

브라우저 테스트는 모든 설정의 UI 노출, 설정·키 저장, 채팅 렌더링·스트리밍, 세션 전환·취소·새로고침, 폴더 선택과 좁은 화면을 검증합니다. 모의 LLM, 로컬 SSE 서버, 임시 소스 fixture로 실행 흐름, 충돌·용량·참조, 컨텍스트 제외 반복, 실패 시 보존, 스트림 인자 조립·끊김, 원문 재조회와 소스 변경을 검증합니다. 외부 API 키 없이 실행됩니다.

```sh
cargo run -- evaluate --suite eval/suite.toml --output eval/results/run-001
```

평가는 실제 API 요청을 사용합니다. 작은 Rust fixture와 이 저장소에 대해 완전 구현 / 기억 재사용 제한 조건을 각각 최소 3회 실행합니다. 두 조건 모두 같은 모델·작업 예산을 사용합니다. 제한 조건은 기억 본문 검색·로드와 자동 기억 목록을 끄되 목표·대화·원문 재조회는 유지합니다. 이것은 모든 형태의 기억이 없는 기준이 아닙니다.

소스 지문, 생성 문서, 시간, 토큰, 체크포인트·기억 조회 횟수, 조사·검증 수와 주제 키워드 포함 여부를 기록합니다. 소스가 바뀌면 중단합니다. 키워드 포함률은 예비 검사이며 사실 오류·근거 정확성은 별도 검토자가 채워야 합니다. 비용은 공급자 가격에 따라 토큰 집계에서 계산하세요.

OpenCode 비교는 동일 소스 지문, 같은 모델·요청, 비슷한 시간·총 토큰 예산으로 별도 3회 실행하고 같은 평가표로 채점합니다. 이 저장소는 OpenCode를 설치·실행하지 않습니다. 실제 모델 평가와 OpenCode 대비 품질 우위는 아직 확인되지 않았습니다.

### 문서 조사·검증 도구

`source-docs`에 문서 목차·섹션 조회(`document_inspect`), 섹션 단위 수정,
출처 일괄 점검(`document_audit`), 조사 항목 일괄 검증(`verify_batch`),
선언 검색(`symbol_search`)이 포함된다. 파일 읽기는 실제 줄 수와 줄 위치를 제공한다.
설정 화면의 **실행과 예산**에서 작성·검증 예산 비율과 반복 조회·중단 제한을 조절할 수 있다.
상세 사용법과 검증 범위는 [문서 도구 개선](docs/documentation-tools.md)을 참고한다.
